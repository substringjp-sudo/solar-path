## 1. 가설·기대 효과·판정 범위
- **H**: 실제 NWP 고리로 만든 Barnes 운량 B 의 오차 T − B 에는 지형에 묶인 성분이 있다. 바람받이 비탈은 예보보다 흐리고 풍하는 맑다.
  - 관측점 탐측(U, N, T, RH)과 DEM 으로 만든 선형 지형 강제 F 를 운량 보존 결합기로 B 에 더하면, 바뀐 양 ΔC 가 그 오차와 같은 쪽을 가리킨다.
  - 즉 **ρ_res = corr(ΔC, T − B) > 0**(방향)이고, **바뀐 양이 참값 오차를 넘지 않는다**(진폭: ΔMSE_W ≤ 0, 곧 β_res ≥ 1/2).
  - 그 신호는 **바람에 홀수**다. 바람을 뒤집으면 바람받이와 풍하가 바뀌어 ρ 가 떨어진다.
  - 그리고 **그날 바람에 묶인다**. 같은 사이트 다른 날의 탐측으로 만든 ΔC 보다 그날 ΔC 가 더 맞다.
- **될 수 있는 이유** [from doc §2.1]: 블렌드의 유효 해상도는 IFS 63~72 km, ICON ~91 km 입니다. 12~50 km 지형의 바람받이·풍하 무늬는 예보에 거의 없고, 지형에 위상이 고정돼 자리까지 자료로 정해지는 유일한 아격자 구름입니다(조사서 §2.3).
  - 이 자가 실제로 재는 것은 **앱 Barnes 바탕 B 에 빠진, 바람에 홀수인 지형 무늬** 입니다.
  - 그것이 예보 자체에 없는 12~50 km 무늬인지, 예보가 이미 일부 푼 40~100 km 무늬(이중 계산·고리 표본 오차)인지는 ρ_fine 과 D_dc(§4.5)로만 가릅니다.
- **안 될 수 있는 이유**
  - Terra ~09:40 지방시의 아침 경계층은 안정하고 바람이 약합니다.
  - 계곡 안개와 찬 공기 웅덩이는 바람과 무관하게 낮은 곳을 흐리게 해 ρ 를 음으로 끕니다.
  - 눈 오탐이 있습니다. 쌓인 눈은 그날 결빙고도 아래에도 남고 비탈 방향에 묶입니다.
  - 상층운 아래에서는 흰 정도 마스크가 C3 가 바꾸는 저·중층을 재지 못합니다.
  - 예보 값 자체의 오차가 큽니다(NWP 몫 0.179 [measured, ringtruth §8.2]).
  - n 이 작습니다.
- **화면 효과**: 산악 장면에서 바람받이 거시 운량은 늘고 풍하는 줄어듭니다(12~80 km).

### 2.9 판·재현(입력이 다시 사라지거나 바뀌어도 판정이 서게)
- **판정 입력은 커밋 파일**입니다: `oro-inputs.json` 과 `dem-grids.json`. 판정은 원자료를 다시 받지 않아도 돕니다(검토 P4).

  - `dem-grids.json`: 사이트마다 6 km 평균 h(128², float32 base64)와 12 km 상자 최고 h(64²). ≈ 0.9 MB [estimate].
- **DEM 판**: `dem-manifest.json` 에 타일마다 z/x/y·sha256·ETag·`x-amz-version-id`(없으면 '없음')·Last-Modified·받은 시각.
  - 다시 받은 타일의 sha256 이 다르면 판정은 커밋 격자로 하고, 다른 타일을 §10 에 적습니다.
  - 앱은 실행 때 살아 있는 타일을 받습니다. 뒤에 AWS 가 타일을 바꾸면 앱 ≠ 자가 됩니다(한계로 적음). G5 는 manifest 타일로 잽니다.
- **탐측 판**: `sounding-manifest.json` 에 사이트마다 요청 URL·받은 시각·원응답 sha256·변수별 null 수·응답 `elevation`.
  - Open-Meteo 보관은 다시 처리될 수 있고, best_match 는 어느 모델을 썼는지 알려 주지 않습니다. 그래서 판정은 원자료가 아니라 `oro-inputs.json` 의 장면별 값을 읽습니다.
  - 확장 범위는 새 파일 이름(`sounding-manifest-extN.json`)으로 받고 덮지 않습니다. RULER-regime 의 확장 탐측도 다른 이름으로 받습니다(검토 p11 d).
- **고리 판**: `ring-manifest.json` 에 `ring/nwp/blend/<site>.json` 의 sha256. 값은 `oro-inputs.json`.
- **은행 판**: `bank-manifest.json` 에 복원 은행 장면 JSON 과 `trueGrid` 의 sha256(값 없음).
- **코드 판**: `versions`(python, numpy, Pillow, node, esbuild 고정 판, chromium 경로·판, SwiftShader 깃발)와 `runtime`(B 번들, G1 하네스 번들, G1 기준 커밋)을 FROZEN 에 적습니다(§9.2).

## 3. 모형(구현 그대로 — `oro_ref.py`(동결)와 `oroLift.ts`(동결 뒤)가 같은 식)
### 3.1 규약
- **격자**: 행이 북쪽으로 증가, 열이 동쪽으로 증가. 관측점은 (n/2, n/2)(`macroField.ts:76-77`).
- **FFT**: `cloudFlow.ts` `fft2`(정방향 e^{−i(kx+ly)}, 역방향 /n²).
  - k = 2π·fftfreq(n, Δ) 는 열(동)에, l 은 행(북)에 붙습니다.
- **바람**: 부는 쪽 벡터 (U 동, V 북) m/s.
  - Open-Meteo 의 오는 방향 d 에서: U = −S sin d, V = −S cos d. 앱은 `weather.ts:896-911` 에서 이미 부는 쪽으로 바꿉니다.
- **기호**: σ = Uk + Vl, K = √(k² + l²), f = 2Ω sin φ(Ω = 7.2921e-5).
- **fastscape 과 견줄 때**: fastscape 는 북쪽이 위인 래스터(행 0 = 북)에 v = +S cos d 로 둡니다. 우리 격자로 옮길 때 v 부호를 뒤집습니다.

### 3.2 h_eff
1. h = max(elev, 0) 을 6 km 칸 평균합니다(§2.4, `dem-grids.json`).
2. 상자 평균을 뺍니다.
3. Tukey 창을 곱합니다(바깥 16 칸 = 96 km, 코사인). 판정 창(±90 km)은 상자 끝에서 ≥ 290 km, 창이 깎이기 시작하는 곳(±288 km)에서 ≈ 200 km 떨어집니다 [computed].
4. 고역: ĥ_sub = ĥ·(1 − e^{−K²s²/2}), s = 10 km. **A1 은 이 단계 뒤의 rms** 입니다.
5. 막힘 자르기: 물리 공간에서 h_eff = clip(h_sub, ±\|V_ref\|/N).

### 3.3 기둥 변위 η_w(주, D1) — Smith 1980 분산 관계 + S&B 2004 의 τ_c → ∞ 극한
- η̂_w(k, l) = ĥ_eff · D(σ) / (1 − i·m·H_w), D(σ) = σ²/(σ² + σ_min²). k = l = 0 이면 0 입니다.
- m 의 갈래:

| 갈래 | 조건 | m |
|---|---|---|
| 전파 | f² < σ² < N² | sgn(σ)·K·√((N² − σ²)/(σ² − f²)) |
| 소멸 | σ² ≥ N² | +i·K·√((σ² − N²)/(σ² − f²)) |
| 회전 | σ² ≤ f², K > 0 | +i·K·√((N² − σ²)/(f² − σ²)) |

- N 은 §3.5 의 마른 N 입니다(습윤 N_m = 0.6 N 은 민감도).
- fastscape 의 갈래(m = 0·abs)와의 차는 고역과 σ_min 을 거친 뒤 rms 0.06 % 입니다 [computed].
- η_w = Re(ifft2(η̂_w)), **F = κ·η_w**(전체 물 PDF 의 σ 단위).
- 뜻: η_w = (1/H_w)∫₀^∞ η(z) e^{−z/H_w} dz. 바람받이 비탈에서 +, 풍하에서 − 이고, 오르막 극한 iσĥ/(NKH_w) 과 무늬 상관 0.94 입니다 [computed].
- 진폭은 대략 U/(N·H_w) 에 비례합니다. 실수부 1/(1 + m²H_w²) 는 h 와 같은 위상이라 F 에는 지형 높이와 같은 쪽의 짝수 성분이 있습니다(합성 T3 에서 corr(η_w, h_sub) +0.14 ~ +0.39 [computed]).

### 3.4 결합기(차 꼴, 모드 1 의 Barnes `base` = B 에)
- **B 의 출처(자·앱 같음, 검토 P5)**
  - B = `buildMacroField(samples, {n: 128, cellKm: 6, noise: false}).base` 입니다(인자는 `applyScene` 의 호출과 같게). Float32 그대로 쓰고 u8 로 양자화하지 않습니다.
  - 번들은 G1 기준 커밋(main 을 합친 뒤, 바꾸기 전)의 `macroField.ts` 를 고정 판 esbuild 로 묶은 것(`runtime`)이고, 동결 파일 `oro-base.mjs` 가 장면마다 총·저·중·상 네 B 를 만듭니다.
  - `oro_ref.py`·`oro.py` 는 B 를 다시 만들지 않고 이 값을 읽습니다. 장면·밴드별 sha256 은 `oro-inputs.json` 에 있습니다.
- **식**
  1. q₀ = Φ⁻¹(clip(B, Φ(−2.5), Φ(2.5))).
  2. δ = 0 에서 시작해 최대 10 번 되풀이합니다.
     - R = G*[Φ(q₀ + F + δ) − Φ(q₀)] 를 구합니다.
     - max\|R\| ≤ 0.005 이면 멈춥니다.
     - 아니면 δ ← clip(δ − R / max(G*φ(q₀ + F + δ), 1e-6), ±1.5).
  3. ΔC = Φ(q₀ + F + δ) − Φ(q₀), C = clip(B + ΔC, 0, 1).
- **G**: 가우스 σ_G = 20 km(반치폭 47 km), 3σ 에서 자름, 비주기. 상자 안 가중합으로 정규화합니다.
- **Φ·Φ⁻¹**: Φ 는 Abramowitz–Stegun 7.1.26 erf, Φ⁻¹ 은 Acklam 근사입니다. 참조와 앱이 같은 근사를 씁니다.
- **실패(A6)**: 10 번 뒤 max\|G*ΔC\| > 0.01 이면 a = 0 입니다. 자는 B_tot 하나로, 앱은 저·중 밴드마다 잽니다(둘 중 하나라도 실패하면 앱 a = 0).
- **a = 0 이거나 `macroOro: 0` 이거나 모드 2(D9) 이면 계산하지 않고 B 버퍼를 그대로** 둡니다.
  - 직접 꼴 Φ(Q̄ + κη) 는 F = 0 에서도 B 를 바꿉니다(자름이 걸리는 B < 0.0062 · > 0.9938, float32 왕복). 차 꼴은 입력을 그대로 돌려줍니다(T5 `array_equal` 참 [computed]).
- **난수**: 결합기는 `mulberry32` 를 쓰지 않습니다. `newState`·`st.beta` 도 건드리지 않습니다.
- G-rev·G-shuf·ρ_rot·민감도 팔도 같은 함수를 씁니다(F 만 다름).

### 3.5 탐측에서 오는 값(MODIS 시각 보간 뒤)
- **기준 고도**: z_ref = 관측점 50 km 안 6 km 칸의 max(0, h) 평균.
- **기준 면**: L = {p ∈ {850, 700} : Z(p) ≥ z_ref + 500 m}. 비면 a = 0 입니다.
  - 덴버는 850 hPa 가 땅속이라 L = {700} 입니다.
- **기준 바람**: V_ref = L 의 면 바람 벡터 평균.
- **안정도 N²**: p_lo 와 p_hi 사이에서 구합니다.
  - p_lo = L 의 가장 낮은 면입니다.
  - p_hi 는 p_lo 가 850 이면 700, 700 이면 500 입니다.
  - N² = (g/θ̄_v)·(θ_v,hi − θ_v,lo)/(Z_hi − Z_lo). θ_v 는 T·RH·p 에서 구합니다(Bolton e_s, q = 0.622e/(p − 0.378e)).
  - 모형에는 N = clip(√N², 0.003, 0.02) 를 씁니다.
- **두 면의 평균**: T̄·RH̄ 는 같은 두 면의 평균, γ = −(T_hi − T_lo)/(Z_hi − Z_lo) 입니다.
- **H_w** = R_v T̄²/(L γ) 를 [1.5, 4] km 로 자릅니다. γ ≤ 0 이면 2.5 km 입니다.
- **C_lm** = 1 − (1 − low)(1 − mid): 고리 0 번 점(블렌드, MODIS 시각)의 값입니다(`oro-inputs.json`).
- **s_rel**: 0.05 ≤ C_lm ≤ 0.45 이고 RH̄ < 0.97 이면 clip((1 − RH̄)/(−Φ⁻¹(C_lm)), 0.05, 0.30), 아니면 0.15 입니다.
- **κ** = γ_s(T̄)/s_rel, γ_s(T) = LΓ_d/(R_v T²) − g/(R_d T).
  - 상수: L 2.5e6, R_v 461.5, R_d 287.04, g 9.80665, c_p 1004.7, Γ_d = g/c_p.
  - 이 γ_s 는 마른 단열로 들린 공기 덩이의 d ln q_s/dz 입니다.
- 한계: V_ref 는 관측점 한 점의 best_match 바람입니다(일본은 JMA MSM 5 km). 덴버 풍하나 해안처럼 이미 지형에 흐트러진 바람을 바람 위쪽 흐름으로 쓰는 셈입니다(검토 m7 → §6 민감도).

### 3.6 어느 레인에
- **자(주 판정)**: 총운량 B_tot = Barnes(고리 총운량) 에 F 를 줍니다. MODIS 는 총운량 마스크라 층을 가르지 못합니다.
  - F3 는 고리 입력의 복원만 확인합니다. 128² B 는 `oro-inputs.json` 의 장면별 sha256 으로 고정합니다(ringtruth 의 바탕은 256² u8 이라 같지 않음).
- **앱**: 저층(R) 과 중층(G) 밴드의 B 에 **같은 F** 를 주고, 상층(B 채널)은 그대로 둡니다. 텍스처 A 채널은 255 그대로입니다.
  - `macroTileCover`(타일 운량 상한)는 이번 회차에 바꾸지 않습니다(D10). 날씨 키와 타일 바이트가 그대로 남습니다. 대신 앱에 보이는 쪽을 c8 이 판정합니다(§4.4).
- **앱 경로 팔(c8·G7·G5(c))**: 원자료의 저·중·상 고리로 밴드별 Barnes 를 만들고, 저·중에 결합기를 따로 돌린 뒤, 무작위 겹침으로 총운량을 만듭니다(§4.4).

### 3.7 앱 배선(판정 대상 아님 — 가드만)
- **옵션** `macroOro: 0 | 1`(기본 0).
  - `DEFAULT_VOLUMETRIC_OPTIONS`·하네스 `JOB_BASE_OPTIONS`(`macroOro: 0`)·개발 설정·`qKey` 에 넣습니다.
  - 날씨 키·`qKey` 문자열에는 **켜졌을 때만** 붙입니다(끈 상태의 키가 바뀌지 않게, 검토 P11).
- **새 관측점 요청(D6)**: 925/700/500 hPa 바람·10 m 바람·저·상층 운량을 **별도 요청**으로 받고 자기 null 캐시를 둡니다.
  - 기존 `fetchThermoProfile`·`fetchLayerWinds` 의 URL·캐시 키는 그대로입니다.
  - `macroOro` 나 `regime` 이 1 일 때만 보냅니다(검토 P11). 둘 다 0 이면 망 요청 목록이 바꾸기 전과 같아야 합니다(G1(d)).
  - null 이면 a = 0. 보간은 §2.3 대체 규칙과 같은 함수입니다.
- **DEM**: `demCpu.loadCpuDemBlock`(디코드 주입, 캐시 없음)으로만 받습니다(D8). 덮음이 1 이 아니면 a = 0. 첫 `applyScene` 뒤에 도착하면 장면을 다시 열쇠로 묶어 다음 재구성에 반영합니다(튐 없이, G2).
- **입력** `VolumetricSceneInput.oro` 는 h 격자 또는 F 입니다. DEM 은 비동기라 호출자가 받아 넘깁니다.
- **F 캐시**: `macro` 객체에 둡니다. 다시 계산하는 때는 다음 둘뿐입니다.
  - (V_ref 방향 10° 칸, \|V_ref\| 1 m/s 칸, N, H_w, κ) 가 바뀔 때.
  - 장면이 바뀔 때.
- **지형에 묶인 ΔC 의 이류(D7)**: 적용 장면(a = 1)에서만 다음과 같이 합니다.
  - 60 s 마다 B(t) = B 를 CPU 에서 `setMacroDrift` 가 (t − 장면 시각) 에 쓸 이류 벡터만큼 옮긴 것(쌍선형, 가장자리 처리는 지금 텍스처와 같게)으로 두고, C(t) = 결합기(B(t), 고정 F) 를 저·중 밴드에 돌립니다(밴드당 수 ms).
  - 그 텍스처의 `setMacroDrift` 이류는 0 입니다. T_sun 의 CPU 읽기(`volumetricScene.ts:1416-1440`)도 같은 텍스처를 이류 0 으로 읽습니다.
  - t = 장면 시각에서 C(t) 는 판정한 C 와 같습니다(G9(a)).
  - a = 0 장면·옵션 끔·모드 2 에서는 지금 `setMacroDrift` 그대로이고 타이머를 만들지 않습니다(G1(d)·G2).

## 4. 지표(모두 `oro.py`, 판정 때 한 번)
### 4.1 공통
- **참값 T**: `trueGrid` 256² × 3 km 를 2×2 평균해 128² × 6 km 로 만들고, 행을 뒤집습니다(북 → 남).
- **지표의 ΔC** 는 C − B(자름 뒤)입니다. r = T − B.
- **판정 창**: 칸 중심이 관측점에서 \|x\|, \|y\| ≤ 90 km 인 30×30 칸입니다. 이것을 12 km 상자(2×2 칸) 15×15 = 225 개로 나눕니다. 상자 값은 상자 안 6 km 칸의 평균입니다.
- **가림 M**(상자 단위, 판정에만 씀 — 앱 동작과 무관)
  - **눈**: 상자 안 최고 h(`dem-grids.json`)가 z_snow − 300 m 이상. 쌓인 눈은 그날 결빙고도 아래에도 며칠에서 몇 주 남으므로 지난 21 일의 최솟값을 씁니다(검토 V2). 덴버 판정 창은 서쪽으로 −106.04° 까지라 대륙 분수령과 4,300 m 봉우리를 품습니다 [computed, 검토 V2].
  - **상층운**: 상자 평균 B_hi ≥ 0.3. B_hi 는 같은 고리 응답의 `cloud_cover_high`(MODIS 시각 보간)로 만든 Barnes 이고 MODIS 를 쓰지 않습니다. 상층운 아래에서는 흰 정도 마스크가 저·중층을 재지 못합니다. 얇은 권운은 안 보이고, 두꺼운 상층운은 아래를 가립니다(검토 V3).
  - **빈 화소**: §2.8 ③(판정 때만).
  - 판정 창 밖(c4·c5)에도 같은 M 을 12 km 상자 바둑판으로 펼치고, 3 km 칸에서는 4×4 칸으로 씁니다.
- **상자 집합**
  - W = 판정 창 225 상자 − M.
  - S = {b ∈ W : \|ΔC_b\| ≥ 0.02}. \|S\| ≥ 20 이어야 합니다(A7; 빈 화소 가림은 A7 에 넣지 않음).
  - S∪ = {b ∈ W : \|ΔC_b\| ≥ 0.02 또는 \|ΔC_rev,b\| ≥ 0.02}. S∪ ⊇ S 입니다.
- Pearson 이 분산 0 이라 정의되지 않으면 그 값은 0 입니다(보수적).

### 4.2 주 지표와 진폭
- **ρ_res** = Pearson_{b ∈ S}(ΔC_b, r_b).
- **주 지표 ρ\*** = ρ_res. 단 동결 전 D_dc 규칙(§4.5)으로 ρ_fine 이 될 수 있습니다. 어느 쪽인지는 FROZEN `decisions` 에 적습니다.
- **β_res** = Σ_{b∈W} ΔC_b r_b / Σ_{b∈W} ΔC_b²(원점을 지나는 기울기). A7 을 넘은 장면은 분모가 0 이 아닙니다.
- **ΔMSE_W** = mean_W[(C_b − T_b)² − (B_b − T_b)²] = mean_W[ΔC_b² − 2ΔC_b r_b]. ΔMSE_W < 0 은 β_res > 1/2 과 같습니다.
- ρ_res 는 ΔC 의 크기를 보지 않습니다. κ 가 2 배가 돼도 ρ_res 는 같습니다. 그래서 진폭은 이 둘로 잽니다(검토 V1). sd(r) ≈ 0.25 [from doc, ringRmseTrue 0.254] 에서 ρ 0.05~0.15 이면 sd(ΔC) < 0.025~0.075 여야 ΔMSE_W < 0 입니다 [computed, 검토 V1].

### 4.3 대조(바람·날짜·지형)
- **G-rev(바람 뒤집기, D3)**: (U, V) → (−U, −V) 로 뒤집고 나머지 입력은 모두 그대로 둔 채 F_rev·결합기·ΔC_rev 를 다시 만듭니다.
  - **짝 차** d = Pearson_{S∪}(ΔC, r) − Pearson_{S∪}(ΔC_rev, r). 둘 중 하나라도 정의되지 않으면 그 장면의 d 는 0 입니다.
  - 같은 집합이라 장면은 하나도 빠지지 않습니다. c3 의 장면 집합은 c2 와 같습니다(검토 O-B1). 서로 다른 집합에서 잰 두 ρ 를 빼면 null 에서 d 의 SD 가 1.0~1.8 배 커지고 상자 고르기 차가 섞입니다 [computed, 검토 sim1].
  - corr(ΔC, ΔC_rev)(S∪)의 중앙값은 −0.79 라 d 의 신호는 ρ_res 의 ≈ 1.8 배입니다 [computed, 검토 sim1b].
  - **높이에만** 묶인 착시(골짜기 안개·찬 공기 웅덩이·고른 눈선)는 바람에 짝수라 **평균적으로** 지워집니다. 바람받이·풍하 신호는 홀수라 두 배가 됩니다.
    - 그러나 판정 창이 지형을 자르므로 장면마다 corr(F, h) 와 corr(F_rev, h) 가 ±0.1 까지 다릅니다(중앙 0.24·0.27 [computed, 검토 sim1b]). 우세풍이 한쪽이면 그 몫이 d 에 남습니다(r_h = 0.3 이면 ≤ 0.03).
  - **비탈 방향에** 묶인 착시는 홀수라 G-rev 로 지워지지 않습니다: 북사면 잔설, 아침 해를 받는 비탈의 눈 밝기(09:40 해 방위 ≈ 138°, 고도 ≈ 32° — 40°N, 10 월 중순 [computed, 검토 V2]; CorrectedReflectance 는 비탈 조도 보정을 하지 않음 [model]), 바람받이에 쌓인 눈. 이것은 눈 기억 가림과 G-shuf 가 맡습니다.
  - **ρ_even·ρ_odd**(보고): ρ_even = (ρ′_res + ρ′_rev)/2, ρ_odd = (ρ′_res − ρ′_rev)/2, 둘 다 S∪ 에서 잰 값(′)입니다. 지형 높이 착시는 ρ_even 에, 바람받이·풍하 신호는 ρ_odd 에 모입니다.
- **G-shuf(날짜 섞기, 검토 V2·O-B4)**: 사이트 s 의 판정 장면 j 마다 다음을 합니다.
  - 같은 사이트의 다른 판정 장면 k(k ≠ j)의 탐측 값(V_ref, N, H_w, κ, s_rel; σ_min·막힘도 k 의 U·N 으로)과 사이트 s 의 DEM 으로 F_{j|k} 를 만들고, **장면 j 의 B_j** 에 결합기를 돌려 ΔC_{j|k} 를 얻습니다.
  - ρ_{j|k} = Pearson_{S∪_j}(ΔC_{j|k}, r_j), ρ̄_shuf,j = k 에 대한 평균.
  - **d_shuf,j** = Pearson_{S∪_j}(ΔC_j, r_j) − ρ̄_shuf,j. 같은 상자 집합에서 잽니다.
  - 뜻: 사이트에 고정된 무늬(비탈 방향 밝기, 오래 남는 잔설, 해안, 고리 기하)는 한 사이트의 장면들에 걸쳐 평균하면 두 항에 같은 몫으로 들어가 지워집니다. 남는 것은 그날 바람에 묶인 몫뿐입니다.
  - 우세풍이 한쪽인 사이트에서는 참 효과가 있어도 d_shuf 가 작습니다. 그래서 c3b 실패는 불합격이 아니라 **미결** 입니다(§5.2).
  - 그날 바람과 함께 내린 눈은 G-shuf 도 지우지 못합니다. 그 몫은 가림에만 기댑니다(§8).
  - ρ_odd,swap(같은 계산을 ρ_odd 로)도 보고합니다.
- **ρ_rot(지형 돌리기, 위약)**: DEM 을 관측점 둘레로 180° 돌린 뒤(바다 0 자름도 그 뒤) 같은 탐측·B 로 ΔC_rot 를 만들어 Pearson_{S∪}(ΔC_rot, r) 를 잽니다. null 이면 0 근처여야 합니다. 평균 회귀 몫(corr(T − B, B) < 0 과 corr_S(ΔC, B) ≠ 0)도 여기에 드러납니다(검토 O-B4·M8).
- **MODIS 없이 미리 적는 값**: corr_S(F, h_sub), corr_S(F_rev, h_sub), corr_S(ΔC, B) 를 `oro-apply.json` 에 적습니다(§2.6).

### 4.4 앱에 보이는 쪽(검토 V3)
- **앱 경로 팔**: 고리 저·중·상으로 B_lo·B_mid·B_hi(Barnes)를 만들고, 저·중에 같은 F 로 결합기를 따로 돌립니다(밴드마다 자기 δ). C_hi = B_hi.
  - 상한 전 총량: ΔC^app = [1 − (1 − C_lo)(1 − C_mid)(1 − B_hi)] − [1 − (1 − B_lo)(1 − B_mid)(1 − B_hi)](G7 에 씀).
- **밴드별 상한**: τ_band = `macroTileCover`(그 밴드의 고리 0 번 값과 150 km 안 고리 점 p75 의 최대). C^vis_band = min(C_band, τ_band), B^vis_band = min(B_band, τ_band).
- **보이는 총량**: C^vis = 1 − (1 − C^vis_lo)(1 − C^vis_mid)(1 − B^vis_hi). B^vis 는 같은 식을 B 로. ΔC^vis = C^vis − B^vis.
  - 1판의 min(C, τ_tile)(총운량과 τ 하나)은 앱 상한이 밴드별(`volumetricScene.ts:1114`)이라 쓰지 않습니다.
- **ρ_res^vis** = Pearson_S(ΔC^vis, T − B^vis). ΔMSE^vis = mean_W[(C^vis − T)² − (B^vis − T)²](보고).
- **풍하 대비 L⁻** = mean_{b∈S, ΔC_b ≤ −0.02}(r_b) − mean_{b∈W}(r_b).
  - 창 평균을 빼서 NWP 의 전체 과다(meanErr +0.044 [from doc])와 권운 맹점을 지웁니다.
  - 그런 상자가 없으면 L⁻ = 0 입니다(c8 에서 "< 0" 을 못 넘는 쪽으로 보수적). ΔC^vis 로 잰 L⁻^vis 도 보고합니다.
- **화면 무게(보고)**: ΔMSE_W 를 관측점 15 km 안(상자 중심 기준 4 상자, 머리 위)과 15~90 km(지평선 띠)로 나눠 적습니다. 저층 운량 면적의 90 % 가 관측점 15 km 안에 있고, 노을 쪽 지평선 띠는 15~90 km 상자에서 옵니다(조사서 §2.1 [from doc]).

### 4.5 규모(검토 V4)
- **나눔**: X_coarse = G₁₀ ⊛_M X, X_fine = X − X_coarse 입니다. X ∈ {ΔC, r}.
  - G₁₀ ⊛_M 은 가림을 존중하는 정규화 가우스 합성곱입니다: G₁₀*(X·m)/G₁₀*m, m = 1(M 밖 6 km 칸), σ 10 km, 3σ 에서 자름, 비주기. 가린 칸의 값이 이웃 상자로 새지 않게 하기 위해서입니다.
  - σ 10 km 의 반진폭 파장은 53 km 로 지형 고역 s 와 같은 띠입니다 [computed].
  - 6 km 격자에서 나눈 뒤 상자 평균합니다.
- **ρ_fine** = Pearson_S(ΔC_fine, r_fine), **ρ_coarse** 도 같은 꼴입니다. 둘 다 보고합니다.
  - 근거: 고역(s = 10 km)은 63 km 파장을 39 %, 100 km 를 18 % 통과시키고, 결합기 보존(σ_G 20 km)이 누르는 몫은 63 km 에서 14 %, 100 km 에서 45 % 쯤이라 ΔC 에는 40~100 km 에 힘이 남습니다 [computed, 검토 V4]. 그 규모는 블렌드가 지형을 이미 일부 푸는 규모입니다.
- **이중 계산 진단 D_dc**(MODIS 없음, 동결 전): 장면마다 corr_W(F, B − G₂₀*B)(상자 값, σ 20 km)를 잽니다. B 가 이미 F 의 무늬를 품고 있으면 + 로 나옵니다.
  - 판정 held 장면의 **중앙 D_dc ≥ 0.3 이면 주 지표를 ρ_fine 로 바꿔 동결** 합니다. 짝짓기 전이므로 허용됩니다.
  - 바뀌면 c2·c3·c3b·c6 의 ρ·d·d_shuf 도 모두 fine 판으로 잽니다. c2b(ΔMSE)는 앱이 보이는 진폭이라 총량 그대로입니다.
  - 값과 결정은 §0.5 와 FROZEN `decisions` 에 적습니다. 짝짓기 뒤에는 바꾸지 않습니다.
- ρ_hp(1판)는 이것을 가르지 못합니다. G*ΔC ≈ 0 이라 분자가 ρ_res 와 같고 40~100 km 성분이 그대로 남습니다(§4.6 보고만).

### 4.6 보조·나눔(보고만 — 판정·꼬리표를 바꾸지 않음)
- **Δcorr12·Δcorr50·ΔmeanErr**(c4·c5 에 씀)
  - C 와 B 를 256² 로 쌍선형으로 올린 뒤 `macro.py` 의 corr12(12 km 미끄럼 상자, ±90 km)·corr50·원반 meanErr 와 **같은 식**을 쓰되, 가림 M 의 칸(3 km 로 펼침)을 C·B·T 모두에서 뺀 판(`oro.py` 안)으로 잽니다(검토 V2(c)).
  - corr12 는 가림 칸과 겹치는 미끄럼 상자를 빼고, corr50 은 상자 안 가림 밖 칸만 평균하며(가림 밖이 절반보다 적은 상자는 뺌), 원반 meanErr 는 가림 밖 칸만 평균합니다.
  - Δ = (C 대 T) − (B 대 T). 가리지 않은 값은 보고만 합니다.
- **ρ_hp**: 잔차의 고역 r − G*r 에 대한 ρ. 분자는 같고(G*ΔC ≈ 0) 분모가 작아 크기가 커집니다. 주 지표를 대신하지 않습니다(검토 M1).
- **바람받이/풍하 대비**: W 에서 F 의 위 삼분위와 아래 삼분위의 평균 r 차를 구하고, 그 부호가 + 인 장면의 비율.
- β_res 의 중앙값·구간, ΔMSE^vis.
- **\|S\| 가중 Fisher z 평균**(가중 \|S\| − 3)과 그 날짜 블록 구간(검토 M4).
- **사이트 표**: 사이트별 n·중앙 ρ\*·중앙 d·중앙 d_shuf, 사이트 하나 빼기(LOSO) 중앙값, **사이트 중앙값들의 중앙값**(검토 O-B2·m5).
- **나눔**: 단일 통과 부분집합(c6 과 별도로 n·중앙·L95), 원 13 날짜와 확장 날짜, 궤도 가로 거리 ≤ 430 km / 그 밖(검토 m3 — 시야 천정각 55~65° 에서 3~5 km 높이 구름은 4~11 km 옮겨짐 [computed, 검토 m3]), DEM h = 0 칸이 절반 넘는 상자를 뺀 판(해안, 검토 m6), **해 쪽 비탈을 뺀 판**(상자 평균 비탈 방위가 통과 시각 해 방위 ±45° 안이고 경사 ≥ 5° 인 상자를 뺌; DEM·궤도 시각만, 비탈 밝기 착시 진단), Nh/U(≤ 1, 1~3, > 3), 지면 역전(T925 > T2m), seam.
- **노을 적용 비율**(MODIS 없음, 동결 전 `sunset-apply.json`, 검토 V5): 같은 탐측 파일로, 사이트마다 06-01 ~ 10-31 의 해 −2° ~ +8°(저녁) 시각에 A1~A5 가 참인 비율을 셉니다. 고리가 있는 09-01 ~ 10-19 는 A6 까지 셉니다. 앱이 노을에 얼마나 자주 움직일지를 사용자에게 보입니다.
- **m8 셈**(§2.6): 판정이 앱 동작의 어느 몫을 덮는지.

### 4.7 통계
- 장면마다 값을 하나씩 내고, 판정 장면들의 **중앙값** 을 씁니다.
- **구간**: 날짜 블록 부트스트랩(블록 = 달력 날짜, 그날의 모든 사이트). 10,000 번, 씨앗 20261103, 백분위 95 %.
  - `eval-ringtruth.py date_block_ci` 와 같은 꼴입니다. 함수는 `oro.py` 로 옮겨 쓰고, 원본은 커밋 파일을 덮어쓰므로 실행하지 않습니다.
- **정확 검정(D11, 검토 O-B2)**: 날짜 블록 부호 뒤집기.
  - 판정 장면의 날짜 G 개마다 그날 값의 부호를 함께 뒤집습니다. G ≤ 16 이면 2^G 가지를 모두 셉니다(≤ 65,536). G > 16(동결 뒤 확장)이면 무작위 65,536 가지(씨앗 20261103)와 항등을 씁니다.
  - 통계량은 중앙값, 한쪽 p = #(뒤집은 중앙값 ≥ 관측값)/(가짓수) ≤ 0.025 입니다.
  - 가정은 "날짜 블록 안 값의 분포가 0 에 대해 대칭" 입니다.
  - 이유: 날짜 블록이 ≤ 16 개라 백분위 L95 > 0 의 실제 한쪽 오류율은 2.5 % 가 아니라 3.5~4.8 %(사이트 효과 없음), 4.8~6.1 %(사이트 SD 0.05), 7~11 %(0.10)입니다 [computed, 검토 sim2]. 부호 뒤집기는 1.7~1.9 %, 효과 0.10 의 검정력 0.41~0.42 입니다(L95 만이면 0.51~0.55) [computed, 검토 sim2b].
- **추론 범위**: 날짜 블록은 사이트를 고정합니다. 이 자의 결론은 "이 held 산악 사이트들의 9~10 월(+ 확장) Terra 아침" 에 대한 것입니다. 다른 산이나 계절로 넓히지 않습니다. 사이트 ≤ 6 곳으로는 사이트 사이 일반화를 판정할 수 없습니다.
  - 사이트 하나 빼기는 판정 조항으로 쓰지 않습니다. 한 사이트 착시(denver +0.25)를 거의 막지 못하고(0.22 → 0.21), L95 를 요구하면 검정력이 0.57 → 0.24 로 떨어집니다 [computed, 검토 sim2b·sim2c]. 사이트·날짜 두 방향 부트스트랩도 너무 보수적이라 쓰지 않습니다 [computed, 검토 sim2].
- **검정력(동결 전, `power-oro.json`)**: 실제 `oro-apply.json` 의 장면 수·날짜·사이트·단일 통과 배치로 통계 검토의 모의를 다시 돌립니다. c2·c2b·c3·c3b·c6·c8 과 정확 검정을 모두 넣은 동시 통과 확률을 참 중앙 ρ 0, 0.05, 0.10, 0.15 에서 적습니다(검토 O-B3·P-B2; RULER-grain2 의 P_FF·검정력 관례).
  - 참 중앙 ρ 0.10 에서 동시 통과 확률이 0.2 보다 낮으면, 동결 전에 사용자에게 알리고 진행·장면 확장·조항 변경 가운데 고르게 합니다(MODIS 없이 정함).

### 5.2 행동(위에서부터 처음 걸리는 줄을 따르고, 실패한 조항은 모두 적음)
1. **가드 실패(짝짓기 전)** → 고친 뒤 가드만 다시 잽니다(검토 P1).
   - 고침이 §3·§4·`oro_ref.py`·`oro.py`·`oro-apply.json` 을 바꾸면, 짝짓기 전이므로 **3판으로 다시 동결** 합니다. §10 에 차이와 이유, 새 FROZEN 해시를 적습니다.
   - 두 판의 판정 값을 함께 내지 않습니다.
2. **c1 이 §2.7 끝까지 안 맞음** → **미결**.
3. **c2 와 c3 이 모두 통과**
   1. c3b 실패 → **미결**("사이트에 고정된 지형·지표 무늬와 구분 안 됨").
   2. 아니고 c2b 실패 → **불합격**("방향 합격·진폭 과대"). 옵션은 끈 채 둡니다. 다음 자에 κ × β̃_res(held 중앙값)를 사전값으로 등록합니다. 이 자 안에서는 κ 를 바꾸지 않습니다. 다음 자는 새 날짜로만 판정합니다.
   3. 아니고 c8 실패 → **불합격**("바람받이 쪽만 맞음 — 앱에서는 타일 상한에 잘려 거의 안 보이는 쪽"). 옵션은 끈 채 두고, 타일 상한(D10)을 다음 회차 후보로 올립니다.
   4. 아니고 c4·c5·c6 가운데 하나 실패 → **불합격**(아래 꼬리표).
   5. 아니면 → **합격**(아래 합격 꼬리표).
4. **c3 통과·c2 실패** → **미결**("η_w 의 짝수 성분이 아침 안개·웅덩이와 반대일 수 있음", 검토 V5).

   - 오후 위성 팔을 다음 자에 등록합니다. 불합격으로 적지 않습니다.
5. **c2 통과·c3 실패** → **불합격**("바람과 무관한 지형 상관(눈·안개 등)").

- **불합격 꼬리표**(검토 O-B3; 옵션과 코드는 꺼진 채, 바이트 같음):

  - 판정을 바꾸지 않는 결함(보고 표·민감도 팔)은 기록만 합니다(grain2 §8.3 선례).

## 8. 함정
- **방향**: 함정이 다섯 군데 있습니다.
  - macroField 는 행 0 = 남입니다.
  - `trueGrid` 는 행 0 = 북입니다.
  - Terrarium 은 y 가 남쪽으로 늘고, demCpu 는 (동, 남) 입니다.
  - 바람은 오는 방향과 부는 방향이 섞여 있습니다.
  - `fft2` 의 부호가 iσ·e^{imz} 의 부호를 정합니다.
  - 하나만 틀려도 ρ 부호가 조용히 뒤집힙니다 → G6 (a)~(e). 참값 쪽(행 뒤집기·2×2 평균·창 색인)은 G6 (f) 가 끝까지 지납니다.
- **땅속 면과 모델 차**
  - 바다 깊이(→ max(0, ·)).
  - 덴버 850 hPa 가 땅속입니다(→ §3.5).
  - 관측점 탐측은 best_match(동아시아는 JMA, 3 시간 기압면 → §2.3 대체 규칙)이고 고리는 ECMWF+ICON 블렌드라 모델이 다릅니다. 기록만 합니다.
  - V_ref 는 관측점 한 점입니다(→ §6 ecmwf 탐측).
- **MODIS 쪽**
  - 눈 오탐(덴버·삿포로 10 월, 확장 날짜). 쌓인 눈은 그날 결빙고도 아래에도 남고 비탈 방향에 묶입니다 → 21 일 눈 기억 가림 + G-shuf. G-rev 만으로는 못 막습니다. 그날 바람과 함께 내린 눈은 G-shuf 도 못 지워 가림에만 기댑니다.
  - 얇은 권운 맹점과 두꺼운 상층운 → 상층운 가림. 가림은 그 몫을 줄일 뿐입니다.
  - Terra 한 시각(~09:40)과 multiPass 합성 규칙 미확정(closest 0.661 대 latest 0.324 [measured, ringtruth §8.2]).
  - 계곡 안개·찬 공기 웅덩이(바람에 짝수 → G-rev). c2 를 끌어내리므로 "c3 통과·c2 실패" 는 미결입니다.
  - 판정 창의 이음매(→ A8), 시야각 시차(→ 궤도 가로 거리 나눔), 해안 착시(해면 반사·해무·`land` 오프셋 → 해안 나눔), 낮은 해의 지형 그림자(→ 확장 해 고도 ≥ 20°).
- **선형 모형의 한계**
  - 예보가 이미 푼 지형을 이중으로 셉니다(s = 10 km 도 63 km 파장을 ~39 % 통과하고, 결합기는 100 km 아래를 거의 누르지 않음) → ρ_fine·D_dc(§4.5).
  - Nh/U > 1 이면 막힘 비선형(자르기는 경험칙).
  - 균일 U·N 으로는 갇힌 풍하파를 못 만듭니다. 5~10 km 파는 나이퀴스트 12 km 아래입니다.
  - 주기 상자 줄무늬(창 + σ_min).
  - 바다·평지는 0 입니다.
- **결합기**: B ≈ 0 이나 1 이 발자국 전체를 덮으면 자유도가 없습니다. 예보가 맑은 상자에 모자구름을 만들 수 없습니다. 상층운으로 B_tot 가 높으면 자의 결합기는 그 상자에서 ΔC 를 거의 못 내지만 앱(저·중)은 움직입니다 → 상층운 가림·G7.
- **앱 표시**
  - 타일 운량 위로 더하지 못합니다(D10) → c8.
  - 지형에 묶인 ΔC 는 D7 재구성으로 산에 남습니다(→ G9). 재구성 사이 60 s 동안은 텍스처가 멈춥니다(10 m/s 에서 600 m, 칸 6 km 보다 작음).
  - 앱 128²(6 km) 와 이전 자들의 256²(3 km)가 다릅니다. **이 자의 판정은 128² × 6 km 에만 해당** 합니다.
- **DEM**
  - hamburg 는 z5 입니다.
  - main 의 `getDemTileUri` z0 후퇴는 조용히 틀린 지형을 줍니다(→ `demCpu` 만).
  - `demTiles`·`demCpu` 는 three(main 에서는 react-native 까지)를 끌어옵니다 → `oroLift.ts` 는 순수하게 둡니다. main 을 합치면 volsky 하네스 번들도 `demTileCache` 를 끌어오므로 대체 모듈을 넣습니다(§9.1 ②).
  - Mercator 와 등장방형의 차가 있습니다.
  - 기기 디코드(Skia)와 Pillow 의 색 관리 차(→ G5(d)).
  - 살아 있는 타일이 뒤에 바뀌면 앱 ≠ 자(§2.9).
- **복원**
  - GIBS 재처리로 은행이 바뀔 수 있습니다(F2).
  - 장면 사본에 `trueGrid` 가 들어 있습니다(G8). `index.json` 에 `cover` 가 들어 있습니다(§0.1).
  - 커밋 파일을 덮어쓰는 스크립트가 있습니다(§2.5). 같은 폴더에 더 받으면 `index.json` 이 덮입니다(§2.7).
  - esbuild 판이 lockfile 에 없습니다(→ 판 고정).
  - Open-Meteo 한도를 공유 IP 가 함께 씁니다(→ §2.5 ④).
  - 고리 점 `cell_selection=land` 오프셋(평균 7~10 km).
- **확장 날짜**: 늦가을이라 해 고도·눈·역전이 다릅니다(합친 집합으로만 판정, 따로 서술).
- **고친 뒤에도 남는 한계**(검토 V §4): 판정 시각은 아침 한 번뿐이고 노을은 눈 판정만 봅니다. 21 일 눈 기억은 경험칙입니다. 흰 정도 마스크는 C3 가 바꾸는 저·중층을 직접 재지 않습니다. 균일 U·N, 관측점 한 점의 V_ref, 고리 표본 오차가 그대로 남습니다.
