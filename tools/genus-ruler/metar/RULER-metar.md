# RULER-metar — 예보가 그리는 저층(운량·운저·강수) ↔ METAR 실링미터 (2026-10-25, 짝짓기 전에 고정)

사용자: "METAR 실링미터로 다음 자 진행해줘." 배경: RULER-genus2 §7 — 관측자 구름 **종류**는 예보로 못 맞힌다(상한 +4.5 %p). 그러나 앱이 실제로 그리는 양은
종류가 아니라 **저층이 얼마나 덮였나·밑면이 어디인가·비가 오는가** 다. 이 셋은 공항이 기계(실링미터·강수 감지기)로 매시간 재므로 관측자 종류보다 객관적인 정답이다.

## 1. 질문
1. 예보 저층 운량(`cloud_cover_low`)이 METAR 저층 누적 운량(2 km 아래 층, FEW 19·SCT 44·BKN 75·OVC 100 %)을 얼마나 맞히는가. 특히 **덮개**(BKN/OVC 저층)를 가르는가.
2. 앱의 저층 **밑면**(`cloudProfile.lowDeck`: 기압면 운량 단면의 저층 봉우리 반값 아래 경계)이 METAR 가장 낮은 운저와 얼마나 맞는가. 응결고도(LCL = 125 m/°C × (T−Td))·기후값(홀수 날 중앙값)보다 나은가.
3. 예보 강수(`precipitation` ≥ 0.3 mm, 앱의 ns 문턱)가 METAR 현재 날씨의 비·눈(RA/DZ/SN, SH 포함)과 맞는가.

## 2. 정답·입력
- 정답: Iowa State Mesonet ASOS 보관(공개) METAR, 네트워크 **KR__ASOS(한국)·JP__ASOS(일본)** — 앱이 실제로 쓰이는 곳. 2026-10-10 ~ 10-23 UTC, 정시(HH:00 ±5 분) 보고만. skyc1~4·skyl1~4(ft AGL)·wxcodes·기온·이슬점·원문.
  - 저층 누적 운량 = 밑면 < 2,000 m AGL 인 층 중 최대 옥타 %(누적이라 최대 = 가장 높은 층 값). CAVOK·CLR·SKC·NSC·NCD = 0 %. 층 정보도 CAVOK 류도 없는 보고는 버림.
  - 운저 = 밑면 < 2,000 m 인 가장 낮은 층(ft → m). 저층 운량 0 이면 없음.
  - 비·눈 = wxcodes 에 RA·DZ·SN·SG·PL(FZ 포함) 이 있음. VC(근처) 만 있는 것은 아님으로.
  - 수직시정(VV)은 OVC 로.
- 입력: Open-Meteo forecast(best_match, start_date 과거) 공항 좌표·그 시각: cloud_cover_low/mid/high, precipitation, temperature_2m, dew_point_2m, boundary_layer_height, weather_code, 기압면 운량·지오포텐셜 높이(1000~700 hPa). `pairmetar.py`, 관측소 10 곳씩, 429 Daily 면 멈추고 이어서(자정 UTC 뒤).
- 지면 높이 = Open-Meteo `elevation`. 앱 lowDeck 밑면은 해발이므로 METAR AGL 운저에 지면 높이를 더해 비교(둘 다 해발 km).
- 나누기: **홀수 날로 문턱·후보 선택, 짝수 날로만 보고.**

## 3. 후보(닫힌 목록)
### 3.1 덮개 판정(METAR 저층 ≥ 75 % 인가)
| 후보 | 내용 |
|---|---|
| C0 | 예보 저층 운량 ≥ T_cov(홀수 날 격자 40·50·60·70·80) |
| C1 | C0 또는 (예보 강수 ≥ 0.3) |
| C2 | 예보 저층·총운량·경계층 높이·강수의 로지스틱 회귀(참고 상한, numpy 직접) |
### 3.2 밑면(METAR 운저가 있고 예보 저층 ≥ 20 % 인 시각)
| 후보 | 내용 |
|---|---|
| B0 | 앱 그대로: lowDeck 밑면(단면), 덱 없으면 LCL |
| B1 | LCL(지상 기온·이슬점)만 |
| B2 | 기후값: 홀수 날 METAR 운저 중앙값(상수) |
| B3 | B0 와 LCL 의 **낮은 쪽**(밑면은 응결고도 아래로 못 내려가지 않지만 덱이 실제보다 높게 잡히는 편향을 보려는 것) |
| B4 | B0 에 홀수 날 중앙 편향을 뺀 것(상수 보정) |
### 3.3 강수
| 후보 | 내용 |
|---|---|
| P0 | 예보 강수 ≥ 0.3 mm(앱 ns 문턱) |
| P1 | 예보 강수 ≥ T_p(격자 0.05·0.1·0.2·0.3·0.5) |
| P2 | P1 또는 weather_code 가 비·눈 코드(51~67·71~77·80~99) |

## 4. 합격선(짝수 날)
- 덮개: 정확도 ≥ 다수 찍기 + **10 %p** 이고 덮개 재현율 ≥ 0.5, 정밀도 ≥ 0.5. 넘는 가장 단순한 후보를 "예보 저층 운량을 그대로 그려도 되는 근거" 로 적는다. 못 넘으면 §160 의 METAR 덮어쓰기가 왜 필요한지의 수치가 된다(지금 시각 외에는 어쩔 수 없음).
- 밑면: 후보 중 짝수 날 **MAE 최소**를 고르되, B0 가 아닌 후보가 B0 보다 MAE 15 % 이상 작을 때만 앱을 바꾼다. 보고: MAE·중앙 오차(부호)·±300 m 안 비율.
- 강수: 정확도 ≥ 다수 찍기 + 5 %p 이고 비 재현율 ≥ 0.5·정밀도 ≥ 0.5. P0 가 넘으면 그대로, P1/P2 만 넘으면 ns 문턱·코드 사용을 바꾼다.
- 추가로(판정 아님) "METAR 가 그림을 바꾸는 비율": |예보 저층 − METAR 저층| > 30 %p 또는 밑면 차 > 500 m 또는 비 유무가 다른 시각의 비율. §160 덮어쓰기가 얼마나 자주 발동하는지.

## 5. 사전 예측
- 덮개: 유럽 SYNOP 전천 N=8 에서 운량만으로 +1.7 %p 였다. 저층 BKN/OVC 는 조금 낫겠지만 **+10 %p 는 못 넘을 것**(예상 +4~7). 재현율 0.5 는 T_cov 50 근처에서 넘을 것.
- 밑면: B0 MAE 400~600 m, 중앙 편향 양수(덱이 실제보다 높음, 기압면 간격 250~500 m 때문). LCL 은 적운 날엔 좋고 층운 날엔 나쁠 것. B3 가 B0 보다 10 % 안쪽으로 나을 듯 — 15 % 는 아슬아슬.
- 강수: P0 재현율 0.3~0.4(약한 비를 모델이 0.1 mm 아래로 둠), P1 0.1 문턱에서 재현율 0.5 넘고 정밀도 0.4~0.5. 날씨 코드 추가는 재현율을 더 올리지만 정밀도를 깎을 것.
- 함정: 일본 자동 관측(NCD)·CAVOK 가 많아 저층 0 % 가 다수 → 다수 찍기가 높다. Open-Meteo 일일 한도 — 짝짓기는 UTC 자정 뒤.

## 4′. 짝짓기 전 수정(2026-10-25 저녁, 설계 판정단 지적 — 자료는 아직 짝짓지 않음)
- **불균형 라벨 함정**: 일본 자동 관측(NCD)·CAVOK 가 많아 "덮개 아님"·"비 안 옴" 이 다수라, 정확도 ≥ 다수 찍기 + 10 %p 는 덮개를 하나도 못 맞혀도 넘을 수 있는 자. 1차 지표를 **ETS(Gilbert 기술 점수)** 로 바꿈: 덮개 합격 = ETS ≥ 0.20 이고 재현율·정밀도 ≥ 0.5; 강수 합격 = ETS ≥ 0.20 이고 재현율·정밀도 ≥ 0.5. 정확도·다수 찍기는 보고만. 예보 저층 운량을 덮개 확률로 본 Brier 기술 점수(기후 기준)도 보고.
- **낮/밤 층화**: 앱이 노을·밤 앱이고 다른 자(위성 일사·DNI τ)는 전부 낮만이라, METAR 가 밤에도 있는 유일한 정답. 덮개·강수·밑면 모두 낮(해 ≥ 0°)·밤으로 나눠 보고하고 합격은 **둘 다** 넘어야 함.
- **후보 추가 B5**: 기압면 RH 가 2 km 아래에서 처음 90 % 를 넘는 높이(이웃 면 선형 보간, 그 아래가 이미 90 % 이상이면 면 − 125 m). `cloud_cover_{p}hPa` 가 Open-Meteo 에서 RH 로 근사된 값이라 B0 와 거의 같을 것으로 예측(기대 MAE 차 < 5 %). 재서 기록용. 이를 위해 pairmetar.py HOURLY 에 relative_humidity_{p}hPa 8 면 추가(요청 가중 26 → 34 변수).
- 그 외 합격선·후보·나누기는 그대로.
