## 0. 무엇을 왜
- **§174(아치 빛)** — 해가 진 뒤 그늘 속 구름은 같은 고도의 맑은 하늘보다 **붉다**.
  - **이 자의 사진 증거는 견고한 사진 하나(P1)와 모호한 사진 하나(P2)** 입니다(통계 검토 #1).
  - P1(해 −9.84°): 덮개/맑음 R/B, 같은 고도 맞춤 D1m = 2.05 / 1.93 / 2.03 / 2.20 (Display-P3 → sRGB), ICC 를 무시하면 1.85 / 1.75 / 1.83 / 1.95 [measured]. 방위 블록 부트스트랩 5 % 분위는 모든 칸 ≥ 1.62 [measured]. 처리·정의를 바꿔도 모든 변형이 ≥ 1.39 [from doc, 통계 #11].
  - P2(−6.92°): E5 부호는 정의 16 개 중 9 개(56 %)에서만 ≥ 1 [measured]. 부트스트랩에서 1 아래일 확률 0.43(7.5~8.5° 칸) [measured] → **보고만**.
  - 지금 렌더러는 그늘 구름에 천정 반구 조도(`GetIrradiance·2π`, 방향 없음)만 줍니다. 그래서 P1B D1m(표시) = 1.17 / 0.81 / 0.94 / 1.11 [measured, 고침 전 번들].
  - heda/critic.md Q5 의 "P2 가 P1 의 부호 실패를 되풀이" 는 이 자에서 받아들이지 않습니다. 문서 쪽 정정은 나중에 docs 에서 합니다.
- **§172(T_sun)** — 해 12° 아래에서는 층 그림자 지도가 꺼지고 해 쪽 2차 행진은 ~6.5 km 입니다 [computed, 절차 #3]. 그래서 해 쪽 먼 구름도 층 안의 스치는 광학두께도 가까운 구름의 햇빛을 막지 못합니다.
  - P3(+1.108°)에서 가까운 회색 판은 그늘이고 먼 해 쪽 밑면은 금빛입니다.
  - 렌더는 가까운 덮개를 빛띠만큼 칠합니다: C1 = 1.07(표시)·1.60(장면 선형) 대 사진 5.57(ICC 무시)·8.07(P3) [measured].
- **§173**: 거시 격자 등록 버그(북쪽 20.34 km @36.05N) 고침. 같은 고침이 24 km 종류 타일 원점도 0.85 타일 옮겼으므로, P1 '오늘' 값은 화소로는 재현되지 않습니다 [from doc, 절차 #8]. 그래서 §5.0 에서 새로 잽니다.
- **§175**: 요약 패널·빔·τ 의 해가 엔진 해로 바뀌었습니다. 이 자의 해는 처음부터 엔진(NOAA) 해만 씁니다.
- **두 손잡이를 한 자로 재는 이유**: 아치 빛은 "해 쪽 지평선 하늘 휘도 × T_arch" 라서 해 쪽 투과율 없이는 서쪽 흐림을 못 가립니다. 판정은 따로 합니다.
  - T_sun: R-A + C1.
  - 아치 빛: D1m + D2 + 반사실·동쪽 대조 + 아치 항 탐침(§4.0).
- **범위 밖**: 먼 껍질(§172.5 P2) · 400 km 광선 결정 · 예보 오차(A 장면은 보고만) · R-B 본체(해 −1 ~ −6°, 새 사진 필요 — §7) · 기기 자리 재현 · 앱 기본값 뒤집기(사용자 결정, held-out 사진 뒤 — §4.9).

**계약(구현이 지켜야 하는 것 — 렌더 전 고정, 타당성 M1·M2·m5)**
- **T_sun(x)**: 표본 위치 x 에서 해 방향 투과율입니다.
  - 같은 밀도 함수(모든 층·거시 고리)를 쓰고 **층 안 스치는 경로를 포함**합니다. 해 쪽 `tsunRangeKm` 까지 행진합니다.
  - **지구 그림자를 표본마다** 곱합니다. 가장자리는 부드럽게 하고, 지금의 0.5 km 단단한 자르기를 대체합니다.
  - 해 ≥ 12° 에서는 아무 효과 없습니다(그림자 지도가 맡음).
- **T_arch(x)**: **구름만**의 투과율입니다. **지구 그림자를 곱하지 않습니다** — 곱하면 P1·P2 에서 0 이 됩니다(그림자 높이 95.2·46.7 km [from doc, 타당성 M2]).
  - 방향은 **해 방위 · 표본 수평(고도 0°)의 한 광선**, 범위는 `tsunRangeKm` 까지입니다.
  - T_sun 텍스처의 **따로 된 채널**로, 같은 밀도·같은 보폭 규칙을 씁니다.
  - 이 한 광선을 아래 영역 Ω 전체에 곱합니다(계약 선택 — 그래서 CF 는 구현 점검이지 물리 검증이 아님, 타당성 M4a).
- **아치 빛**: 그늘 표본의 내산란에 다음 항을 더합니다.
  - **E_arch(x) = ∫_Ω L_sky(x, ω) · Φ(ω, v) · dω × T_arch(x)**
  - Ω = {방위 ∈ 해 방위 ± 30°, 고도 ∈ [표본의 지평 내림, +5°]} (표본 기준).
  - 내림 아래(땅)는 0 입니다. 이 영역은 사전 시험의 전구 아치 휘도 중 P1 14~19 %, P2 43~48 % 를 버립니다 [from doc, 사전 시험 — 타당성 m5].
  - L_sky = 앱 15 파장 산란 표(하늘과 같은 표·같은 RGB 변환).
  - Φ: A1 = 1/(4π)(등방), A2 = 렌더러의 해 위상과 같은 이중 HG(같은 g)를 cos∠(ω, 시선)에 씁니다. 둘 다 ∫Φ dω = 1 로 정규화합니다.
  - 해 항과 같은 자리(같은 소산 계수·같은 다중산란 옥타브 인자)에 들어가며 **이득 없음(1.0 고정)** 입니다.
  - 해 고도 θ 의 섞음 w(θ) = smoothstep(−1°, −2°, θ): θ ≥ −1° 에서 0, ≤ −2° 에서 1, C¹ 연속입니다.
  - **채택이 뜻하는 범위는 사진이 있는 −6.5 ~ −10° 뿐**입니다. −1 ~ −6° 는 H1·켜짐 이음매로만 봅니다(타당성 M5).
- T2·A2 는 T1·A1 과 **그 한 값만** 다릅니다. H0 는 T1A1 과 archNoT 만 다릅니다. 판정 뒤 매개변수 맞추기는 없습니다.
- **아치 항 탐침(G-A, §4.1)**: 구현은 디버그 출력으로 표본점의 E_arch(RGB)를 냅니다. 이 값을 CPU 계약 적분기와 견줍니다(§5.0 ⑤).

**고쳐 받아들인 것**:
- **통계 #8 의 "변형 퍼짐을 여유에 더함"** — 여유는 3 × A/A 만 쓰고, 변형 퍼짐은 보고만 합니다.
  - 이유: C0 대 C0ps 는 P1 처럼 직달광이 없는 장면에서도 D3m 이 17~18 % 다릅니다(0.249 → 0.299, 0.459 → 0.544 [measured]).
  - 이 차이는 accurateSunSkyLight 가 하늘빛을 표본마다 셈해서 생기는 **진짜 경로 차이**이지 무관한 변동이 아닙니다. 가드 기준이 C0ps 이므로 여유에 넣지 않습니다.
- **통계 #2b 의 "g_CF ≤ (1 − f_blk)·g_B + 0.05"** — 대신 벽을 키워 f_blk(기하) ≥ 0.973 [computed] 으로 만들고, k = 0.5 를 고정했습니다.
  - 이유: f_blk ≈ 1 이면 그 식은 절대 문턱 0.05 가 됩니다. D1 칸의 무관한 변동(오늘 B 네 변형 사이 ln 최대 0.069 [from doc, 통계 #8])보다 작아 잡음으로 떨어뜨립니다.
  - 등방 가짜는 동쪽 대조가, T_arch 없는 가짜는 CF·H0 가 맡습니다.
- **통계 #3(iii) 의 "P1 노출을 규칙으로 다시 고름"** — ×45(사진 맞춤 표시 노출)는 두고, ×16 두 번째 노출을 합쳐 장면 선형의 발끝만 메웁니다.
  - 이유: D4·D5·박명 색은 표시값이 사진과 맞아야 하는 지표입니다.
- **통계 #3(i) 의 "모든 판정이 두 공간에서"** — **관문만** 두 공간에서 봅니다. 가드는 표시 공간입니다.
  - 이유: 가드는 사진(휴대폰 표시값)과 견주는 띠이고, 장면 공간 가드를 더하면 연언이 두 배가 됩니다(통계 #8).
- **통계 #7 의 "C0ps 가 변별 단위 2/3 실패"** 에 타당성 B2 의 가족 규칙을 함께 넣었습니다.
  - es 가족은 기하상 2 단위뿐이라, 하나만 실패해도 R-A 실패입니다(엄격함을 받아들임).

## 3. 지표(`tsun_photo.py`, 사진·렌더 같은 정의)
### 3.1 색 계산
- 8 비트 값 → 상자 축소(8 비트 공간, 사진 P1·P3 ×4 · P2 ×2 — 비평과 같음) → sRGB EOTF → 선형.
- **사진 주 길 = Display-P3 → 선형 sRGB 행렬**(파일 ICC "DCI-P3 D65 Gamut with sRGB Transfer", 음수 0).
  - 보조 길 = ICC 무시. 비평 재현 검사는 보조 길로 합니다.
  - 표시 luma 지표(D4·D5·E1~E4·C5·C6·박명 색)는 두 길이 같습니다.
- **렌더 표시 선형** = sRGB EOTF(사진과 같은 길).
- **렌더 장면 선형** = three.js `ACESFilmicToneMapping` 역변환입니다.
  - 근거: 앱 합성기 마지막 패스는 postprocessing `ToneMappingEffect(ACES_FILMIC)` → three 의 같은 함수 [from code, volumetricScene.ts:883].

### 4.7 비용(RULER-grain 비용 모형 — 1.5 표 절차 M·§5.6·§8.3)
- cap_cum = min(1.40, 0.9 · 50 / frameMs_C0)(사용자 기기 값 전에는 1.40). 기기 문은 resScale 0.5 유지, 10 초 팬 frameMs EMA ≤ 45 ms.
- **식**(절차 #7): cost(E) = [F_cloud(E)·T + U(E)·N²·S] / [F_cloud(C0)·T]
  - T = W·H·res²/16 (프레임당 구름 텍셀).
  - F_cloud = 텍셀당 구름 패스 읽기(RULER-grain 비용 변형 + **T_sun 조회 앵커 하나 추가**). 앵커가 RULER-grain 고정 앵커 수와 부딪히면 §5.0 에서 멈춥니다.
  - S = T_sun 텍셀당 읽기(T_sun 패스 계수기).
  - U = 프레임당 T_sun 갱신 수(하네스가 16 초·60 fps 대본 팬에서 셈, 못 재면 1).
- **규칙**: (a) 비용 잡(COST 36 + P1B·P2B·P3B) 중앙 cost ≤ 1.15 [estimate] (b) RULER-grain 채택 손잡이까지 합친 누적 ≤ cap_cum. 장부 = RULER-grain `adopt-R*.json` + `tsun-ledger.json`.
- 비용 실패만 있으면 **비용 보류**(채택 안 함, 갱신 빈도 설계로 돌아감).
- 예상 규모 [estimate]: 128² × ~400 걸음 × 3 층 ≈ 2 천만 읽기/갱신. 매 프레임 갱신이면 +25~120 %, 바뀔 때만이면 무시할 만합니다.

### 4.8 깊은 박명 무변화(T 팔만)
T1·T2 는 P1B·P2B(직달광 0)에서 C0ps 대비 D1m·D3m(장면 선형)·E5a·E6a 칸마다 \|Δln\| ≤ max(0.05, 3 × A/A) 여야 합니다. T_sun 이 지구 그림자 속 구름에 빛을 만들면 안 됩니다.

### 4.9 채택(`gate`)
- **T 팔**: R-A + C1 + 가드 전부 → 채택 후보. 둘 다면 비용 낮은 쪽, 같으면 T1.
- **아치 팔**: T1 이 채택 후보 + D1m + D2 + CF + G-A + 가드 전부 → 채택 후보.
  - **그리고 H0 의 CF 가 'fail'** 이어야 합니다(통과·na 면 '반사실 변별 없음', 아치 빛 채택 안 함).
  - 둘 다면 G-A 오차 합이 작은 쪽, 그다음 비용, 그다음 A1.
- 관문은 통과했으나 가드 하나 실패 → 채택 안 함('가드 실패: 이름'). 평가 안 된 가드가 있으면 '가드 미평가' → 채택 안 함.
- **채택 = "손잡이 있음, 기본 끔"**. 앱 기본값으로 켜는 것은 held-out 사진(§7)을 동결 도구로 잰 뒤 사용자가 결정합니다.

## 7. 알려진 한계
- 사진 세 장, 각 한 장면입니다. 부호·크기 규칙만 있고, 칸은 독립 증거가 아닙니다. B 장면은 손으로 만든 추정이라(구름 질감 무작위) 화소 대응이 없습니다.
- **아치 빛 증거 = 견고한 P1 하나 + 모호한 P2 하나**. 관문은 P1 위에만 섭니다.
- 휴대폰 처리(야간 다중 프레임·국소 톤 매핑) 때문에 절대값은 못 쓰고 비의 비만 씁니다. 색상 선택 편집이 부호를 만들었을 가능성은 배제 못 합니다 [from doc]. 다만 P1 D1 은 밝기 층마다 ≥ 1.42 입니다 [from doc, 통계 #11].
- P2 틈 16 % 잘림(E5 칸은 0 % [from doc]), P3 빛띠 7~10 % 잘림.
- 장면 선형은 "합성기 출력 = ACES + sRGB 한 번" 가정에 기댑니다. 합침 점검이 실측 확인입니다(§3.1).
- R-A 기준은 앱의 밀도·하늘빛 모형 안의 '진실'입니다. 아치 빛의 무차별 기준은 없고, 아치 빛은 사진·반사실·탐침으로만 봅니다.
- 후쿠이 시내 불빛이 P1 덮개를 비췄을 수 있습니다(가늠 안 함). D1 이 13~68 km 에서 평평해 D1 을 만들지는 않았다고 봅니다. D3 bin 3~4 는 부풀었을 수 있어 D3 는 띠 가드로만 씁니다.
- R-B 본체(해 −1 ~ −6°)는 아직 사진이 없습니다. 바라는 촬영: 일몰부터 −8° 까지 2~3 분마다 같은 덮개, 해 방위 ±30°, 1 배 렌즈, GPS 또는 같은 순간 앱 화면, 프로 모드·고정 화이트밸런스(또는 RAW). s123.2 원본(후쿠이 10/02 17:28·17:47, 해 −2.7°)을 사용자에게 부탁 [from doc]. 이것이 기본 켬의 held-out 입니다.
