# RULER-tsun — 해 줄 투과율(T_sun)·아치 빛: 사진 자 + 긴 광선 기준 (§172·§174 뒤) — **초안(렌더 전), 2026-10-28**

**사전 등록(예정)**: 이 문서와 §8 의 파일(`tsun_photo.py`·`make-jobs-tsun.py`·`sun-tsun.cjs`·그 출력 `sun-tsun.json`·`scenes-tsun.json`·사진 값 `tsun-photo.json`·오늘 기준 `tsun-baseline.json`)을 **T_sun·아치 빛 손잡이 구현 전에, 판정 렌더를 한 장도 그리기 전에** 커밋합니다. 렌더를 본 뒤 규칙·문턱·장면·판정 코드를 바꾸지 않습니다(바꾸려면 새 자 RULER-tsun2 를 먼저 씁니다).
이 판은 **초안**입니다 — 3 관점(통계·타당성/지각·절차/하네스) 독립 검토(작업 T0)를 거친 뒤 고쳐 동결합니다. 동결 전에는 아무 판정 렌더도 그리지 않습니다.
숫자 꼬리표: **[computed]** 코드로 계산(기하·해), **[measured]** `tsun_photo.py` 가 화소에서 잰 값, **[from doc]** 비평 문서·에이전트 파일·이 저장소 문서, **[estimate]** 판단.
사진 원본은 저장소 밖(사용자 업로드)이며 sha256 으로만 고정합니다(§2).

## 0. 무엇을 왜
- **§174(아치 빛)**: 해가 진 뒤 그늘 속 구름은 같은 고도의 맑은 하늘보다 **붉다** — P1(해 −9.84°) 덮개/맑음 R/B 1.73~1.81 배, P2(−6.92°) 덮개/틈 1.05~1.58 배 [measured·from doc]. 지금 렌더러는 그늘 구름에 천정 반구 조도(`GetIrradiance·2π`, 방향 없음)만 주므로 0.72~1.08 — **부호가 틀림** [measured, §3]. 비평 결론: "D1 과 E5 두 부호 실패가 아치 빛 작업의 관문" [from doc, heda/critic.md Q5].
- **§172(T_sun)**: 해 12° 아래에서는 층 그림자 지도가 꺼지고 해 쪽 2차 행진은 1~7 km 라, 해 쪽 먼 구름도 **층 안의 스치는 광학두께**도 가까운 구름의 햇빛을 막지 못함. P3(+1.108°)에서 가까운 회색 판(6.5~8.25°)이 그늘이고 먼 해 쪽 밑면(1.25~4.25°)이 금빛인데, 렌더는 가까운 덮개를 빛띠만큼 칠함(빛띠/위 R/B 0.90~1.07 대 사진 5.57) [measured].
- **§173**: 거시 격자 등록 버그(북쪽 20.34 km @36.05N — §173 본문의 "21.36" 은 오타, heda/critic.md #10) 고침. 이 자의 P1 장면은 고침 전 번들에 맞춰 **고리를 미리 밀었으므로** 고친 번들에서는 밀지 않은 고리를 씁니다(§2.3).
- **§175**: 요약 패널·빔·τ 의 해가 엔진 해로 바뀜. 이 자의 해는 처음부터 엔진(NOAA) 해만 씁니다.
- **두 손잡이를 한 자로 재는 이유**: 아치 빛 제안(§174.6b)은 "해 쪽 지평선 하늘 휘도 × T_sun" 이라 T_sun 없이는 서쪽 흐림을 못 가림(§4.5). 판정은 따로 — T_sun 은 R-A + R-C, 아치 빛은 R-B-deep + 반사실.
- **범위 밖**: 먼 껍질(§172.5 P2) · 400 km 광선 결정 · 예보 오차(A 장면은 보고만) · R-B 본체(해 −1 ~ −6°, 새 사진 필요 — §7) · 기기 자리 재현 · 앱 기본값 뒤집기(사용자 결정).

- T2·A2 는 T1·A1 과 **그 한 값만** 다름. 판정 뒤 매개변수 맞추기 없음.

## 3. 지표(`tsun_photo.py`, 사진·렌더 같은 정의)
### 3.1 색 계산
- 8 비트 값 → 상자 축소(8 비트 공간, P1·P3 ×4 · P2 ×2 — 비평과 같음) → sRGB EOTF → **선형 sRGB**. 화소 각 [computed]: P1 사진 ×4 0.0852°/화소 = 렌더 0.0852 · P3 사진 0.0172 대 렌더 0.0216 · P2 사진 0.0144 대 렌더 0.0553(렌더가 3.85 배 거칢 — 분위 지표 E5q·E6q 가 화소 크기에 민감할 수 있어 E5 판정은 알파 정의). 사진 ICC(Display-P3)는 무시 — 렌더(sRGB)와 같은 길로 재기 위함(판단).
- **표시 luma** = 0.2126R + 0.7152G + 0.0722B (8 비트 값, 0~255). **선형 Y** = 같은 가중 × 선형값. **R/B** = 영역 선형 R 평균 / 선형 B 평균(화소 비의 평균 아님). 비의 비(R/B ÷ R/B)는 흰색 균형 이득이 지워짐.
- P3 행렬 감도(보고): Display-P3 → sRGB 행렬을 쓰면 D1 1.909~2.007(+10 %), C1 8.07(+45 %), C4 10.2, E5q 1.071·1.393, E8 0.245 [measured]. 부호 규칙(D1 ≥ 1.3, E5 ≥ 1, C1 ≥ 2.5)은 두 색 길에서 같은 판정 — 문턱은 선형 sRGB 값에 둠.

- 규칙(`tsun_photo.py cf B켬 B끔 CF켬 CF끔`, 켬 = 아치 팔, 끔 = 그 T 팔): 칸마다 g = ln(R/B_deck(켬) ÷ R/B_deck(끔)). **통과** = 모든 D1 칸에서 g_CF ≤ ln 1.1 **그리고** g_B > 0.1 인 칸에서 g_CF ≤ 0.5 · g_B. 근거: 사진의 분홍 효과 ln 1.75 = 0.56 의 17 % 이하만 허용; 벽이 +2.2° 위 아치는 못 가리므로 0.5 배 여유 [estimate]. 보고: 15~30° 칸의 deck/clear R/B(벽이 clear 상자에 안 들어오는 칸).
- 하네스가 중층 두께 10 km 를 받지 않으면(결과 `layers` 의 [밑면, 두께] 로 확인) → '반사실 평가 불가'(다른 벽으로 바꾸지 않음; 아치 빛 채택 안 함, 사용자에게).
- 연기 시험(도구 점검만, 의미 없음): obs/ps 렌더 넷으로 g_B 0.00~0.07, g_CF 0.00~0.07 [measured].

### 4.7 비용(RULER-grain 비용 모형을 그대로 — §2.4 fetchCost, §5.5~5.6 누적 장부 cap_cum, §8.3 기기 값)
- 지시문의 "RULER-grain §5.5" 는 채택 규칙 절이고, frameMs 모형은 그 자의 1.5 표(절차 M)·§5.6·§8.3 에 있음 [from doc]: **cap_cum = min(1.40, 0.9 · 50 / frameMs_C0)**(사용자 기기 값 전에는 1.40), 기기 문 = resScale 0.5 유지, 10 초 팬 frameMs EMA ≤ 45 ms.
- 모형: frameMs(E) ≈ frameMs_C0 · fetch(E)/fetch(C0) (텍스처 읽기 지배 가정, RULER-grain 과 같음). fetchCost 는 구름 패스만 셈 → **T_sun 패스는 따로 더함**: 갱신 한 번 = N² × (걸음/텍셀) 읽기, 텍셀 수 대비 fetch 등가로 환산해 프레임마다 갱신 빈도 × 를 더함. 갱신 빈도는 10 초 팬에서 잰 값(해·날씨 바뀔 때만 갱신하면 0 에 가까움), 못 재면 **매 프레임**으로 셈(최악).
- 규칙: (a) 팔의 (fetch + T_sun 패스 등가) ÷ C0 비용 잡 중앙 ≤ 1.15 [estimate] (b) RULER-grain 에서 채택된 손잡이까지 합친 **누적** ≤ cap_cum (c) 기기 후속은 RULER-grain §5.6 의 기기 문. 비용 잡 = RULER-grain §4.4 의 비용 잡 목록 + P1B·P2B·P3B.
- 예상 규모 [estimate]: 128² × ~400 걸음 × 3 층 ≈ 2 천만 읽기/갱신; 기기 구름 패스(0.5 배율) ≈ 1.6~8 천만 읽기/프레임 → 매 프레임 갱신이면 +25~120 %, 바뀔 때만이면 무시할 만함. 비용 실패만 있으면 **비용 보류**(채택 안 함, 갱신 빈도 설계로 돌아감).

### 4.8 깊은 박명 무변화(T 팔만)
T1·T2 는 P1B·P2B(직달광 0)에서 C0ps 대비 D1·D3·E5a·E6a 칸마다 \|Δln\| ≤ 0.05 — T_sun 이 지구 그림자 속 구름에 빛을 만들면 안 됨.

### 4.9 채택
- T 팔: §4.3 통과 + C1·C2 + 가드 전부 → 채택 후보. 둘 다면 비용 낮은 쪽(T1), 같으면 T1.
- 아치 팔: 그 T 팔이 채택 후보 + D1 + E5 + §4.5 + 가드 전부 → 채택 후보. 둘 다면 D1·E5 칸의 \|ln(E/사진)\| 합이 작은 쪽, 같으면 A1.
- 관문은 통과·가드 하나 실패 → 채택 안 함('가드 실패: 이름'). 평가 안 된 가드가 있으면 '가드 미평가' → 채택 안 함.
- 앱 기본값으로 켜는 것은 사용자 결정(RULER-grain 과 같음).

1. **동결**: 3 관점 검토 → 이 문서 고침 → §8 파일·해시 커밋(렌더 0 장). 동결 커밋 해시를 §8 에 적음.
2. **구현**(손잡이 기본 끔, §1 계약): 셰이더 시험(RULER-grain `grain-shader-test.mjs` 방식) → G-T0(§4.1). 옵션 이름 매핑만 §10.
3. **기준 재측정**: 손잡이 번들로 C0·C0ps 를 사진 장면·tw·HS·RA(+ REF) 에 그림. §3 의 '오늘' 값과 견줘 \|ΔD1\| > 0.10 · \|ΔE5a\| > 0.05 · \|ΔC1\| > 0.15 이면 원인을 §10 에 적고 **재측정 값을 B 로**(규칙은 그대로). **재측정 C0 가 이미 D1·E5·C1·C2 관문 중 하나를 넘으면 그 관문은 변별력 없음 → 멈추고 사용자에게.** R-A 변별(§4.3) 확인.
4. **후보 렌더**: 닫힌 4 팔(T1·T2·T1A1·T1A2), **한 라운드**. 잡 = `make-jobs-tsun.py expand`(팔 × 장면, 고리 sha 확인). 하네스는 RULER-grain 보정이 끝나 기계가 빈 뒤에만.
