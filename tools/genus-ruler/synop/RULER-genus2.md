# RULER-genus2 — 예보 → 구름 종류 규칙 재점검 (2026-10-24, 짝짓기 전에 고정)

사용자: "구름 종류 규칙을 신뢰할 수 없다. 제대로 종류를 골라 그리는지 다시 점검해 달라."

## 0. 지금 규칙의 상태(1차 자 RULER-genus-forecast, 2026-09-26~10-03, 짝수 날 보고)
- 저층 4분류 정확도 0.518, 다수 찍기(sc) 0.515 — 거의 "전부 sc". 적운 재현율 0.28(적운 549 중 390 을 sc 로), 층운 0.32, 적란운 0.05.
- 중층: as 재현율 **0**(asCover 101 로 사실상 꺼짐) — 관측 as 130 건 전부 ac 로. 상층: cs 재현율 **0** — 관측 cs 567 건(23 %) 전부 ci 로.
- 1차 자의 결론은 "자를 못 넘음, 기본값 고르기로 읽을 것"이었고 그 뒤 §144·§147·§158 이 사례마다 예외(st 밑면 0.4 km, 비 올 때 as, DNI 시트)를 덧댔습니다.
- 코드 읽기에서 찾은 논리 문제(자료 없이도 보이는 것):
  1. `isRaining` 이면 저층 운량이 20 % 뿐이어도 **ns**(비구름 전체 덮개). 자 쪽 파이썬은 `cl ≥ nsCover(80) 이고 cm ≥ 20` 을 요구 — **TS 와 자가 다릅니다**(TS 는 §147 때 바뀜). 가랑비 0.1 mm 에 저층 24 % 면 하늘 전체가 비구름.
  2. 상층은 **항상 ci**, 중층은 강수 없으면 **항상 ac**: 두께 정보를 안 씀. SYNOP 의 CM 1·2(as)·CH 5~8(cs) 는 관측자가 "해가 흐릿하게 비치는가/안 보이는가" 로 가르는 두께 분류인데, 예보의 DNI(§158)가 바로 그 양.
  3. 앱(liveScene)은 `classifyGenus` 에 **CAPE·LI·기온·이슬점·날씨 코드를 넘기지 않습니다**(obs 에는 capeJkg·pblM 이 있는데도). 그래서 적운 판정은 "저층 덱 두께 ≥ 0.6 km" 하나, 밑면은 단면이 없으면 LCL 도 못 구합니다. 1차 자는 CAPE·LI 를 넣고 쟀으니 **앱이 실제로 돌리는 규칙과 다른 것을 쟀습니다**. 이번 자는 앱과 같은 입력(CAPE·LI 없음)으로 R0 를 재고, R2 에서 경계층 높이·CAPE 를 **앱에도 넘기는** 전제로 잽니다.
  4. 밤(isDay false)이면 적운이 없고 전부 sc — 밤 적운은 드물지만 저녁 하늘의 적운 잔재가 sc 덮개로 바뀌는 튐.
  5. `stOvercast` 예외(§144)는 덮개 구름을 st 로 보내지만, 밑면이 0.4 km 보다 높은 흐린 덮개(대부분의 sc 덮개 0.6~1.5 km)는 sc 로 그려 "흐린데 덩어리" 가 됩니다.

## 1. 질문
운량 외에 예보가 주는 물리량(DNI 두께 τ, 기압면 상대습도·운량 단면, CAPE·LI·경계층 높이·LCL, 강수, 날씨 코드)을 쓰면 SYNOP 관측 종류를 **다수 찍기보다 뚜렷이** 잘 맞히는가. 특히 as·cs 를 0 에서 끌어올리고, cu ↔ sc 혼동을 줄이는가.

## 2. 정답·입력(1차와 같음 + 추가)
- 정답: ogimet SYNOP, 블록 03·06·07·08·10·11·16, **2026-10-10 ~ 10-23**(14 일), 유인(ix 1·2·3), 8NhCLCMCH 있는 보고. CL/CM/CH 매핑은 1차 자와 같음.
- 입력: Open-Meteo forecast(best_match, past_days) 그 시각: cloud_cover_low/mid/high, precipitation, cape, lifted_index, boundary_layer_height, weather_code,
  temperature_2m, dew_point_2m, relative_humidity_2m, is_day, **direct_normal_irradiance, shortwave_radiation**, 기압면 1000~300 hPa 운량·고도·**상대습도**.
  앱이 받는 변수(또는 받을 수 있는 변수)만. 좌표·높이는 NOAA nsd_bbsss.
- 파생: τ_dni(§158 `cloudOpticalDepthFromDni`, 해 ≥ 5° 만), 저층 덱 밑면·두께(lowDeck), LCL, 중층 습윤 면 수(RH ≥ 85 % 또는 운량 ≥ 10 %), 상층 운량 면 수.
- 평가 집합·분류는 1차와 같음(저층 4분류 {Cu, Sc, St, Cb}, 중층 {As, Ac}, 상층 {Ci, Cs}; 모델 그 층 ≥ 20 %).
- 나누기: **홀수 날로 문턱·규칙을 정하고 짝수 날로만 보고.** τ_dni 는 낮 보고만 있으므로 중·상층은 "낮(해 ≥ 5°) 부분집합" 과 "전체" 를 따로 보고.

## 3. 후보(닫힌 목록)
| 후보 | 내용 |
|---|---|
| R0 | 지금 TS 규칙 그대로(파이썬 복사본을 TS 와 **같게** 고친 뒤) |
| R1 | R0 + 두께: 낮에 τ_dni ≥ T_as 이면 중층 as(중층 ≥ T_cov), τ_dni ≥ T_cs 이면 상층 cs; 밤에는 상층 운량 면 수·중층 습윤 면 수로 대신(문턱 홀수 날) |
| R2 | R1 + 저층: 적운 = 낮 · 저층 < cuCover · (LI ≤ cuLi **또는** CAPE ≥ cuCape **또는** 덱 두께 ≥ cuThickKm **또는** 경계층 높이 ≥ pblKm 이고 밑면이 경계층 안); 층운 = 밑면 ≤ stBaseKm 또는 (RH₂ₘ ≥ 95 %·운량 ≥ stCover); ns = 강수 ≥ nsPrecip **이고** 저층 ≥ nsCover(1차 자대로) |

## 4. 합격(1차와 같음)
- 저층 4분류: 짝수 날 정확도 ≥ 다수 찍기 + **10 %p**, cu·st 재현율 ≥ 0.30.
- 중층·상층 2분류: ≥ 다수 찍기 + **5 %p**, 그리고 as·cs 재현율 ≥ 0.30(0 이던 것을 끌어올리는 것이 목적).
- 넘는 후보 중 가장 단순한 것(R1 < R2)을 TS 에 옮깁니다. R3 만 넘으면 "규칙으로는 안 됨" 으로 적고 R3 를 넣을지 사용자에게 묻습니다.
- 못 넘으면 지금 규칙을 두되 1 절의 논리 문제 1(ns 조건)만 고치고 §158 에 "자를 못 넘음" 을 적습니다.

## 5. 사전 예측
- as·cs: τ_dni 하나로 낮 재현율 0.5~0.7 예상(SYNOP 정의가 두께). 밤은 습윤 면 수로 0.3 근처.
- cu: LI 대신 경계층·덱 두께를 쓰면 재현율 0.3→0.5, 대신 sc 재현율이 0.74→0.6 으로 내려갈 것. 정확도 +5~8 %p — **10 %p 는 아슬아슬**.
- 함정: Open-Meteo 일일 한도(이 환경의 공용 IP 가 오늘 429) — 짝짓기는 UTC 자정 뒤 재시도, 관측소 10 곳씩 묶어 요청 수를 줄임.
