# RULER-physics2 — 알갱이를 가른 지표 · 무리만 떼기 · 조명 바닥값 진단 (§137)

**사전 등록**: 이 문서와 `phys2-photo-quartiles.json`(phys2.py 해시 포함)·`jobs-phys2*.json` 은 아래 렌더를 한 장도 그리기 전에 커밋합니다.
렌더를 본 뒤 규칙·문턱·장면을 바꾸지 않습니다. (초안 상태에서는 독립 비판 검토를 받고, 결함을 고친 뒤 고정합니다.)

## 0. 무엇을 왜 하나
§136 에서 물리 소광(P1)·얼음 무리(P2)는 사전 등록한 자(RULER-physics)를 넘지 못했습니다. 사용자 결정(2026-10-14): 22° 무리만 따로 떼어 다시 재고(H1), 알갱이를 걷어낸 새 지표로 흐린 하늘을 다시 재고(R3c),
조명 바닥값이 소광 효과를 가리는지 진단만 합니다(D1). 기기 비교는 하지 않습니다(렌더 하네스 지표와 육안만). 권운 면적 역표 재맞춤·2단계 설계는 이 단계에서 하지 않습니다.

## 1. 편향을 줄이는 구조(꼭 읽을 것)
- §136 의 렌더(P0·P1·P2 × 8 장면 × 방위 200·110·20, 새 지표를 만들기 전에 이미 봄)는 **개발 집합**입니다. 지표가 퇴화하지 않았는지 보는 데만 쓰고 **채택 판정에는 쓰지 않습니다.**
- 채택 판정은 **held-out 집합**(새 날씨 오프셋 `weatherOffsetKm = [7, −5]` km, 새 방위 290·160)에서만 합니다. 이 집합은 규칙 고정 후에 처음 그립니다.
  같은 날씨 생성기·같은 층 설정이라 완전히 독립은 아닙니다(한계, §8).
- 사진 사분위(`phys2-photo-quartiles.json`)는 사진만으로, 후보 렌더를 지표에 걸어 보기 전에 계산·동결합니다. 문턱은 전부 사진 사분위이고 렌더로 조정하지 않습니다.
- 하네스는 같은 코드·같은 입력도 일부 장면(cu·sc·ns·st·as)에서 화소가 흔들립니다(§136.3, 평균 |Δ| ≤ 0.02/255). 규칙의 문턱이 이 흔들림 안의 차이에 걸리지 않게 효과 크기를 요구한 곳을 표시했습니다.

## 2. 지표(`phys2.py`, fm.py·phys.py 는 그대로 가져다 씀)
로그 휘도를 5 화소 상자(R = 2, 폭 320 그림의 1.6 %)로 거른 굵은 성분과 나머지 잔 성분으로 가릅니다(구름 마스크 안쪽, 포화 화소 제외).
- structSD(굵은 성분 표준편차 — 알갱이를 걷어낸 얼룩, 0 이면 "무늬 없는 판") · grainSD(잔 성분 표준편차) · grainShare(= grainSD² / (grainSD² + structSD²)) ·
  coarseDark(굵은 성분이 중앙값의 절반보다 어두운 화소 비율) · coarseRange(p10/p90) · coarseIQR.
- 기존 phys.py 지표(brightRatio·darkRatio·pieceLogSD·cloudFrac)는 R1·R2·G4 용으로 그대로.
- 사진(생각보다 알갱이가 없음): 고층운 grainShare 0.005, 층운 0.016, 난층운 0.020, 적운 0.050, 고적운 0.083; 흐린 하늘 structSD 0.35~0.57.

## 3. 후보
| 후보 | 내용 |
|---|---|
| P0 | 지금(물리 끔). |
| P1 | `physics`(소광·단면). |
| P2 | `physics` + `physicsIce`(§136 과 같은 코드·상수). |
| H1 | `iceHalo`(새): **물리 없이** 얼음 층(ci·cs·cbanvil)에만 22°·46° 무리(상수는 P2 와 같음, 재조정 없음) + 가루 끔은 손값 렌더 기둥 광학두께 < 1 인 얼음 층만(`smoothstep(1, 5, τ_손값_렌더)`). 소광·단면은 손값 그대로. 물 구름 층은 셰이더 입력이 P0 과 같아야 함. |
| F0 | P0 + `debugLightFloors = [0, 0]`(조명 바닥값 치환, 진단용). |
| F1 | P1 + `debugLightFloors = [0, 0]`. |
`debugLightFloors = [s, m]`: 구름 패스의 `max(vec4(0.35), exp(−genusAO·depth))` 의 0.35 → s, `max(vec4(0.28), exp(−0.035·gTau))` 의 0.28 → m 으로 셰이더 글자를 치환(기본 null — 끄면 글자 동일).

## 4. 장면(`make-jobs-phys2.mjs`)
공통: 390×584, `gen`, quality high, res 0.5, 프레임 32, out both. 위치·시각은 §136 과 같음(36.5679 N 136.6774 E 103 m, 2026-10-03 03:00Z, 시선 20°, 시야 60°) + `weatherOffsetKm [7, −5]`.
- held-out 낮 장면(방위 290·160): cu · ac · ci · sc25 · sc85 · st · as · ns(§136 과 같은 종류·운량·밑면). 후보 P0·P1·P2.
- 무리 장면(시선 = 해, 해 방위·고도는 suncalc): hcsH(cs 0.9 @8.5 km, 03:00Z 해 고도 약 49°) · hcsL(cs, 06:00Z 낮은 해) · hciH(ci 0.9 @9 km, 03:00Z) · hciL(ci, 06:00Z). 후보 P0·H1.
- H1 의 ci 가드: ci 장면(방위 290·160) 후보 H1.
- 진단 장면(방위 290 한 방위): cu · ac · sc25 · sc85 · st · as · ns, 후보 F0·F1(바닥값 켠 쪽은 위 held-out 의 P0·P1 을 그대로 씀).
- 박명 가드(G2)는 §136 렌더(P0·P1·P2 모두 통과)에서 옵션을 건드리지 않는 코드라 상태 해시 동일로 대신합니다.

## 5. 규칙 — P1·P2 재판정 (§136 의 R3 를 R3c 로 바꾼 것 외에는 같음)
- R1 종류별 밝기비(held-out cu·ac·ci·sc25·sc85, 밝기비·어두움비 10 칸, 사진 [q25, q75], `phys-photo-quartiles.json`): ○ 수 ≥ P0 그리고 D ≤ 0.85 · D(P0).
- R2 조각 간 밝기 차(cu·ac·ci·sc25, pieceLogSD ≥ 사진 q25, 조각 4 개 이상일 때만): ○ 수 ≥ P0.
- **R3c 흐린 하늘 구조·알갱이**(st·as·ns·sc85, 장면마다 네 칸 — structSD ≥ 사진 q25 · coarseDark ≥ 사진 q25 · grainShare ≤ 사진 q75 · grainSD ≤ 사진 q75): ○ 수 ≥ P0.
- G1 CLIP(AcCc·Ci, `clip/ruler2.py`, held-out 방위 290·160 두 장면으로): 자기확률 ≥ P0 − 0.05.
- G3 끄면 그대로: 셰이더 글자 동일(phys-shader-test.mjs) + 상태 해시(state-hash.js) 동일 — 화소 동일은 요구하지 않음(§136.3).
- G4 운량 면적: held-out 장면마다 cloudFrac 상대 변화 |Δ| ≤ 25 %.
- H(P2 만): held-out 무리 장면 hcsH·hcsL 에서 E22(P2) − E22(P0) ≥ 0.04 (P2 의 무리 대조: |E22(P1) − E22(P0)| ≤ 0.02 — 개발 집합 halo 장면으로 이미 확인).
- 채택: P1 = R1·R2·R3c·G1·G3·G4, P2 = P1 조건을 P2 값으로 + H. 하나라도 어긋나면 기본 끔. 규칙에 없는 조합은 채택하지 않음.

## 6. 규칙 — H1 (무리만)
- HA 무리 이득: E22(H1) − E22(P0) ≥ 0.04(cs: hcsH·hcsL), ≥ 0.02(ci: hciH·hciL). 네 장면 모두.
- HB 물 구름 층 입력 동일: 개발 집합 장면 28 개의 상태 해시가 P0 과 H1 에서 같음(얼음 층이 없는 장면 전부). 얼음 층이 있는 장면(ci 3 개 + halo)만 달라야 함.
- HC 권운 종류 판정: held-out ci(방위 290·160) CLIP 자기확률 ≥ P0 − 0.05.
- HD 권운 밝기비: held-out ci 의 R1 두 칸(밝기비·어두움비) ○ 수 ≥ P0.
- HE 면적: held-out ci·hci* 의 cloudFrac 상대 변화 |Δ| ≤ 5 %(소광을 안 바꿨으니 거의 0 이어야 함).
- 채택: HA~HE 모두. 그러면 `iceHalo` 를 앱 개발 패널의 ICE 칩이 PHYS 없이도 켜지게 하는 것은 **사용자 결정 사항**(코드는 옵션으로만 제공, 기본 끔).

## 7. 진단 D1 — 조명 바닥값 (채택 판정 아님, 2단계 입력)
held-out 방위 290 의 F0·F1(바닥값 0) 과 P0·P1(바닥값 0.35·0.28) 을 견줍니다.
- S1 "바닥값이 어두운 쪽을 제한한다": 어두움비 여섯 칸(ac·sc25·sc85 × P0·P1)에서 바닥값 0 의 값이 바닥값 켠 값보다 사진 중앙값에 사분위 폭의 0.25 이상 가까운 칸이 4 개 이상.
- S2 "바닥값이 소광 효과를 가린다": 부분 덮임 네 장면(cu·ac·sc25·sc85)에서 |darkRatio(P1) − darkRatio(P0)| 가 바닥값 0 에서 켠 쪽보다 커진 장면이 3 개 이상.
- 해석: S1·S2 모두 참 → 바닥값이 주된 제한(2단계에서 바닥값을 물리로 다시 도출); S1 만 참 → 바닥값이 밝게 들어올리지만 소광 효과와는 독립; 둘 다 거짓 → 바닥값 아님(위상·다중 산란 근사를 의심).
- 흐린 하늘(st·as·ns)은 structSD·coarseDark·grainShare 가 바닥값으로 바뀌는 크기를 표로 보고만 함.
- 바닥값은 **켜 보기만** 하고 기본값은 건드리지 않음.

## 8. 예측(렌더 전)
- D1: 바닥값 0 이면 모든 후보의 구름 안 어두운 쪽이 더 어두워져 어두움비가 내려감(거의 확실). S1 참일 가능성이 큼, S2 는 불확실.
- R3c: P0 은 알갱이가 많아 grainShare 칸에서 실패하고 structSD 칸은 통과할 가능성; P1·P2 는 알갱이는 줄지만 st·ns 에서 structSD 가 모자라 실패할 가능성.
- H1: P2 와 같은 상수라 cs 에서 E22 +0.05 근처, ci 는 무리 가중 0.5 라 +0.02 근처로 문턱 걸림 — 걸릴 수 있음(결과 그대로 보고).
- 민감도(보고만): 상자 반지름 1·3 에서 후보 순서가 R = 2 와 같은지.

## 9. 알려진 한계
개발 집합을 본 뒤 만든 지표임(held-out 으로 완화) · held-out 은 같은 생성기 · 사진은 카메라·시야가 제각각이라 화소 척도가 다름 · 렌더 흔들림 · 두 방위 중앙값(= 평균) · 사진은 대개 노출·톤 곡선이 적용된 JPEG.
