# RULER-physics2 — 알갱이를 가른 지표 · 무리만 떼기 · 보조광 진단 (§137)

**사전 등록**: 이 문서·`phys2.py`·`phys2-photo-quartiles.json`(phys2.py 해시 포함)·`jobs-phys2.json`·`eval-phys2.sh`·하네스 번들 해시(§10)를 아래 held-out 렌더를 **한 장도 그리기 전에** 커밋합니다.
렌더를 본 뒤 규칙·문턱·장면·판정 코드를 바꾸지 않습니다(바꾸면 새 자를 먼저 씁니다). 초안은 렌더 전에 독립 비판 3 관점(통계·물리·진단/절차)의 검토를 받았고(§1), 결함을 고친 뒤 이 버전을 고정합니다.

## 0. 무엇을 왜
§136 에서 물리 소광(P1)·얼음 무리(P2)는 RULER-physics 를 넘지 못했습니다. 사용자 결정(2026-10-14): 무리만 따로 떼어 다시 재고(H1), 알갱이를 걷어낸 지표로 흐린 하늘을 다시 재고(R3c),
조명 쪽이 소광 효과를 가리는지 진단만 합니다(D1). 기기 비교는 하지 않습니다(렌더 하네스 지표와 육안만). 권운 면적 역표 재맞춤·2단계(대류 모형)는 이 단계에서 하지 않습니다.
**G4(운량 면적)가 권운에서 P1·P2 의 채택을 이미 막을 것으로 예상**(§136: ci −98 %, 같은 코드·상수)하므로, P1·P2 의 R1·R2·R3c 결과는 **채택 결정이 아니라 2단계 입력**입니다. 채택 후보가 될 수 있는 것은 H1 뿐입니다.

## 2. 지표(`phys2.py`; fm.py·phys.py 를 그대로 가져다 씀 — 둘은 고치지 않음)
로그 휘도를 coarse = 5 화소 상자 평균, large = 구름 마스크 정규화 33 화소 상자 평균으로 거르고
**mid = coarse − large**(5~33 화소 대역 = 구름 얼룩), **fine = logL − coarse**(알갱이)로 가릅니다(폭 320 화소 그림, 구름 안쪽·포화 제외).
- structMid = std(mid) · grainSD = std(fine) · grainShareMid = grainSD² / (grainSD² + structMid²)(노출·톤 곡선 기울기에 무관).
- interior: 렌더 알파 ≥ 0.9 + 5×5 창이 전부 구름, 사진 NRBR 마스크 + 3 화소 더. nInt < 400 이면 NaN.
- 사진 제외: interior 의 0.1 × 중앙값 미만 화소 > 2 %(비구름 물체; 1 % 는 층적운·난층운의 진짜 어두운 영역까지 걸러 완화) 또는 포화 > 1 % → 제외, 사유를 json 에 기록.
- 사진 사분위와 부트스트랩 90 % CI(4000 회, 고정 씨앗)를 `phys2-photo-quartiles.json` 에 동결.
- 기존 phys.py 지표(brightRatio·darkRatio·pieceLogSD·cloudFrac, 알파 ≥ 0.15)는 R1·R2·G4 용으로 그대로(`phys-photo-quartiles.json`).
- 칸 신뢰도: 로그 척도 지표에 톤 배율 {0.85, 1, 1.2} 를 곱해 결과가 뒤집히는 칸은 **무효**(grainShareMid 는 배율 무관). 판정은 문턱 세 벌 — 기본 [q25, q75] · 넓게 [q25 CI 하한, q75 CI 상한] · 좁게 [q25 CI 상한, q75 CI 하한] — 에서 모두 돌립니다.
- 사진 사분위(제외 후, 흐린 하늘): structMid 층운 0.025/0.083/0.134 · 고층운 0.039/0.067/0.108 · 난층운 0.058/0.079/0.110 · 층적운 0.109/0.136/0.208(q25/q50/q75).

## 5. 규칙 — P1·P2 재판정 (정보용: G4 선결 예상, §0)
칸 = (장면, 방위, 지표); 후보와 P0 가 **모두 유한하고** 유효한 칸 V 위에서만 셉니다. 점수 = V 위의 ○ 수, 통과 = 점수(후보) ≥ 점수(P0) + 아래 절대 하한. 방위별 칸이며 방위 중앙값은 쓰지 않습니다.
- **R1** 종류별 밝기비(cu·ac·ci·sc25·sc85, 밝기비·어두움비, 사진 [q25, q75] `phys-photo-quartiles.json`, 최대 30 칸): 점수 ≥ P0 그리고 평균 D ≤ 0.85 × P0 평균 D(D = |ln(v/q50)| / ln(q75/q25)) 그리고 점수 ≥ 0.5|V|; |V| < 18 이면 평가 불가.
- **R2** 조각 간 밝기 차(cu·ac·ci·sc25, pieceLogSD ≥ 사진 q25, 조각 4 개 이상인 칸만): 점수 ≥ P0; |V| < 4 이면 평가 불가.
- **R3c-struct**(st·as·ns·sc85, structMid ∈ [q25, q75], 톤 배율 필터): 세 문턱 벌 모두에서 점수 ≥ P0 그리고 점수 ≥ 0.5|V| 이면 '통과', 기본에서만 통과하면 '불확정', |V| < 6 이면 평가 불가.
- **R3c-grain**(같은 장면, grainShareMid ≤ 사진 q75): 점수 ≥ P0(알갱이가 P0 보다 나빠지지 않을 것), 같은 방식으로 세 벌·|V| ≥ 6.
- **G1'** CLIP 라벨(`clip-labels.py`, held-out ac·ci 방위 5·160·290): 라벨이 맞는 방위 수 ≥ P0(AcCc 는 AcCc, Ci 는 Ci·Cs).
- **G3** 끄면 그대로: 셰이더 글자 동일(`phys-shader-test.mjs`) + 상태 해시 동일(`state-hash.js`, 옛 번들·새 번들 28 장면 224 필드) — 화소 동일은 요구하지 않음(§136.3).
- **G4** 장면별(방위 평균) cloudFrac 상대 변화 |Δ| ≤ 25 %(P0 면적 ≥ 0.02 인 장면만).
- **H**(P2 만): haloGain(P2) ≥ 0.02 — hcsH·hcsL.
- 채택 정책: 후보별로 위 규칙 모두 '통과'. '평가 불가'·'불확정'은 보류(기본 끔). 일부만 통과하면 기록만. 규칙에 없는 조합은 채택하지 않음.
- 폭 민감도(보고만, 판정 아님): 렌더를 폭 260·208 로 줄여 R3c 를 다시 돌려, **결론이 폭에 따라 바뀌면 '불확정'으로 적습니다**(사진 시야를 모름 — §9).

## 6. 규칙 — H1 (무리만; 모두 통과해야 채택 후보)
- **HA 무리 이득**: haloGain(H1) ≥ 0.02 — hcsH·hcsL·hciH·hciL 네 장면 모두(Weber 2 % — 사진 앵커 없음, §9). NaN 이면 평가 불가.

- **HB 물 구름 입력 동일**: 개발 집합 28 장면을 iceHalo 켠 번들로 걸었을 때, 얼음 층이 없는 23 장면은 모든 필드(셰이더 글자·균일변수 개수 포함)가 P0 과 같고, 얼음 층이 있는 5 장면(ci_200·ci_110·ci_20·halo_0·seoul)은 `clouds.shader`·`clouds.uniforms`·`genusHalo`·`genusPowderW`·`genusPhysOn` 만 다름(`state-compare.py`).
- **HC** 권운 라벨: held-out ci(방위 5·160·290) 라벨이 맞는 방위 수 ≥ P0.
- **HD** 권운 밝기비·어두움비: ci 의 R1 칸(최대 6 칸) 점수 ≥ P0(가루를 안 건드리므로 변화 없어야 함).
- **HE** 면적: ci·hci* 의 cloudFrac 상대 변화 |Δ| ≤ 5 %(소광 불변이라 구조상 0 — 환경 점검용).
- H2(가루 끔만)는 **보고만**: ci 의 R1 칸·면적, 무리 장면 대조. P2 의 권운 변화에서 무리와 가루 끔을 가르는 데 씀.
- 채택 후보가 되어도 앱 기본값으로 켜는 것은 **사용자 결정**(코드는 옵션, 기본 끔).

## 7. 진단 D1 — 보조광 (채택 판정 아님, 2단계 입력)
방위 290 의 기준(P0·P1) 어두움비를 네 팔과 견줍니다: F(조명 바닥값 0.35·0.28 → 0), K(하늘빛 `skyLightScale` 0), G(지면 반사 0), T(`thru` 0).
- 어두움비의 사진 거리 D = |ln(v/q50)| / ln(q75/q25)(`phys.logdist`). **유효 칸** = 기준 D ≥ 0.5(사진 사분위 밖) 이고, F 팔은 ao > 0 인 종류(cu·sc25·sc85; ac 는 ao = 0 이라 바닥값이 구조상 무효).
- 설명 몫 f = (D기준 − D팔) / D기준, 유효 칸 중앙값 f. 읽기: f ≥ 0.5 이 항이 **주된 제한**; 0.2 ≤ f < 0.5 **부분**; f < 0.2 **제한 아님**; 유효 칸 < 3 평가 불가. 항을 전부 끈 팔은 두껍고 어두운 구름이 죽으므로 만들지 않음.
- 바닥값·보조광 항은 **켜 보기만** 하고 기본값은 건드리지 않습니다. 흐린 하늘(st·as·ns)의 structMid·grainShareMid 변화는 표로 보고만.
- 해석: 어느 팔도 f ≥ 0.2 가 아니면 보조광 항이 아니라 위상·다중 산란 근사를 의심(재지는 않음).

## 8. 예측(렌더 전, 개발 집합을 본 뒤라는 점을 밝힘)
개발 집합(채택 판정에는 안 씀)에서 새 지표를 돌려 본 결과: P1·P2 의 R3c-struct 점수는 P0 과 같고(3 대 3, 둘 다 절대 하한 0.5|V| 미만) R3c-grain 은 P1·P2 가 더 좋음(8 대 5), R1 은 P1·P2 가 P0 보다 나쁨(15 대 18). 예측: held-out 에서도 R3c-grain 은 P1·P2 가 좋고, R3c-struct 는 P0 과 비슷하며, 절대 하한은 P0 도 못 넘길 수 있음.
H1: P2 와 같은 상수라 cs 에서 haloGain 이 +0.04~0.06 근처, ci 는 가중 0.5 이고 구름이 성겨 문턱 0.02 근처에서 걸릴 수 있음. D1: 바닥값 팔은 ac 에서 변화 없음(ao = 0), 나머지는 불확정.

## 9. 알려진 한계
- 개발 집합을 본 뒤 만든 지표(held-out·사진 사분위 우선 동결로 완화). held-out 은 같은 날씨 생성기·같은 층 설정(시드·오프셋만 다름).
- 사진은 카메라·시야·톤 곡선이 제각각이고 시야를 모릅니다. 렌더 폭 320 으로 화소 척도를 맞췄으나 각도 척도는 다름(폭 민감도로 보고만).
- 사분위 표본이 작음(제외 후 18~28 장) — CI 가 넓어 신뢰할 수 있는 칸이 줄어 '평가 불가'·'불확정'이 나올 수 있습니다(그대로 보고).
- haloGain 문턱 0.02 는 사진 앵커가 없는 지각 문턱(Weber 2 %)입니다. 46° 링은 시야 밖이라 검증하지 않았고 분산 상수도 검증 안 함. 링은 항상 켜진 결정 상한(순수 결정 가정).
- 해 둘레 부채꼴(위쪽 ±50°)만 재서 아래·옆 호는 안 봄.
- CLIP 라벨은 점수가 아니라 argmax 이며 AcCc·Ci 판정기 타당성이 P0 에서도 낮음(§136) — 보조 지표.
- D1 은 보조광 항 하나씩 끈 결과의 읽기일 뿐 인과 증명이 아님(항 사이 상호작용 미측정).
- 하네스(SwiftShader)는 같은 코드도 일부 장면에서 화소가 흔들리지만 이 단계 지표에서는 상대 차 ≤ 1.2e-4 로 무시 가능(§136.3).
