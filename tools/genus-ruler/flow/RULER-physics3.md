## 0. 무엇을 왜
§137 D1: 부분 덮임 장면의 어두움비(구름 p10 ÷ 하늘 중앙값)가 사진보다 2 배 밝고(층적운 렌더 1.80·2.18 vs 사진 0.58/0.95/1.41), 햇빛 확산 투과 항 `thru` 를 끄면 사진 범위로 들어옵니다(f 0.87).
그런데 `thru` 를 끄면 **그늘이 푸르러집니다** — 새 지표 shadeBlue(그늘 B/R ÷ 밝은 곳 B/R, §2) 가 P0 1.3~1.8 → T0 2.0~2.8, 사진은 종류별 q75 가 1.13~1.63. 하늘빛을 끄면(K0) 1.0~1.4 로 희어집니다. 즉 그늘의 빛은 "흰 햇빛 확산 + 푸른 하늘빛" 두 몫이고, 지금은 흰 몫의 **양**이 틀렸습니다.

**원인(코드 읽기, 렌더 전 가설)**: `thru` 는 위쪽 광학두께를 `τ_up = β_표본 × (꼭대기까지 거리)` 로 셉니다 — 표본의 **국소** 소광입니다. 종류 단면은 밑면에서 램프(층적운 `base` 0.08 → 60 m)로 밀도가 0 에서 오르므로, 아래에서 본 광선이 처음 만나는 램프 표본들은 β 가 작아 τ_up ≈ 1~20 으로 보이고 `thru` 는 거기서 **최대(햇빛의 0.28~0.36 / 4π)** 입니다. 실제 그 위 기둥은 τ 100 을 넘는데도요. 램프 자체의 광학두께가 6 이 넘어 보이는 밑면 전부가 이 표본들로 결정됩니다.
같은 표본에서 takram 의 다중 산란 근사(해 쪽 행진 + 그림자 지도의 **진짜 기둥** τ)는 0.01 입니다. `thru` 의 식 (1 − e^(−0.15τ))·2/(2 + 0.1τ) 이 τ 10~20 에서 봉우리인 것 자체는 틀리지 않습니다 — 판의 **확산** 투과(전체 투과 − 직접 투과)도 τ' ≈ 1.5(g 0.85 에서 τ ≈ 10)에서 최대입니다(`phys3-test.mjs` 표). 따라서 식의 모양이 아니라 **τ_up 을 국소 소광으로 센 것**이 결함이고, 같은 기둥 τ 에서는 지금 식과 두-흐름이 양도 비슷합니다(τ 10: 0.365 vs 0.317, τ 165: 0.030 vs 0.051).
물리를 켜 얇아진 층(P1)이 더 밝아진 것(§137 D1: P1 어두움비 2.36·3.24)도 같은 결함으로 설명됩니다: 램프 표본의 국소 β 가 더 작아져 τ_up 이 봉우리 쪽으로 갑니다.

## 1. 후보 — 표본 하나의 광원 (구름 패스만; 그림자 패스는 그대로)
지금(L0 = P0): radiance = sun·MS(τ_sun, cosθ) + 지면반사 + **sky·(1/4π)·skyGradient·max(0.35, e^(−ao·depth))** + **sun·(1/4π)·thru·(1 − e^(−0.15τ_up))·2/(2 + 0.1τ_up)·max(0.28, e^(−0.035τ_up))·max(beamT, 0.25)**; ×산란계수 ×가루.

**기둥 광학두께(세 후보 공통, 해석적)** — 그림자 지도는 쓰지 않습니다: takram 그림자 행진은 minTransmittance(1e-4)에서 끊기고 거리 꼬리를 더해 τ ≈ 72(경사)로 **포화**하므로(검토 물리 1), 거기서 읽으면 밑면 D 가 두께와 무관하게 0.14 근처에 묶입니다.
대신 표본이 속한 층의 **단면을 적분**합니다: τ(hf 구간) = (표본 소광 ÷ 표본 날씨 밀도 합) × H × ∫ gDensity(hf) dhf, gDensity 는 patchGenusShader 와 같은 식(날씨 d 는 weather.depth 에서 되찾음: d = depth + 1 − hs(hf_표본)), 중점 8 개.
τ_above = 표본 위 구간, τ_total = 전체(≥ τ_above). 표본의 모양 잡음 배율이 기둥 전체에 걸리는 것·이웃 구름이 없는 것은 한계(§8). 수직 기둥이므로 μ0 로 세우지 않습니다.
- 비대칭 g = 0.85(물방울; 얼음 층도 같은 값 — 얇아 영향 없음, §8), 축척 τ' = (1 − g)τ. takram 위상(0.7/−0.2 혼합, g_eff 0.25)과 다른 값을 쓰는 이유: 두-흐름의 g 는 매질의 것이고 MS 옥타브의 위상은 보이는 각분포용 렌더 선택(§8).
- 확산 투과 T(τ'_t) = 1 / (1 + 0.75 τ'_t) (점근 이론 4/(3τ' + 4q') 의 q' 를 4/3 로 두어 τ' → 0 에서 1; τ' 1.5 에서 점근값과 15 % 차). 직접광의 각 가중 K(μ0) = (3/7)(1 + 2μ0), μ0 = max(0.05, n·sunDir).
- 확산장(에너지 밀도 ∝ F↓ + F↑, 두-흐름은 τ 에 선형): D = (2 − T)(1 − x) + T·x − (충돌 전 몫), x = τ'_above / τ'_t, D ≥ 0. 햇빛의 충돌 전 몫 e^(−τ'_above/μ0)(축척 직접광 — 전방 봉우리는 takram MS 옥타브가 맡음), 하늘빛은 e^(−2τ'_above)(반구 평균 시컨트 2).
  얇은 층(τ_t → 0): D → 0. 두꺼운 밑면: D → T. 꼭대기(직접광 뺀 뒤): D → 1 − T = R.
- 광원 J = [E_sun·μ0·K(μ0)·D_sun + E_h·D_sky] / 2π. E_sun = takram sunIrradiance(코사인 없음), **E_h = skyIrradiance / 2π**(takram skyIrradiance = 2π × 수평면 하늘 조도 — 검토 물리 2·셰이더 2), 2π 는 등방 반구 둘의 평균 복사휘도 (F↓ + F↑)/2π(검토 물리 3). 정오 sc 밑면(τ 165) 어림: 햇빛 몫 760·0.051/2π ≈ 6.2, 하늘 몫 120·0.051/2π ≈ 1.0 → 흰 6 : 푸른 1.

## 4. 규칙(칸 = (장면, 방위, 지표); 후보·L0 모두 유한한 칸 V 위에서)

  렌더 포화(≥ 250 인 구름 화소 > 1 %, 사진 제외 규칙과 같은 문턱)인 칸은 **측정 불가**(V 에서 뺌): 하네스 노출은 해 고도로 정해져(`autoExposure`) 후보와 무관하고, 포화된 밝은 쪽은 B/R → 1 이라 shadeBlue 를 부풀립니다. 컴파일 점검 렌더(개발 장면 sc85, 프레임 4)에서 L2·L3 의 밝은 쪽이 P0 보다 훨씬 밝아(검토 물리 9 의 예측 — 꼭대기 D-항이 MS 보다 큼) 포화가 보였으므로 렌더 전에 적습니다. 많이 포화하면 |V| < 11 로 '평가 불가' 가 됩니다 — 그 자체가 결과(노출 자 재설계의 입력).
  **통과** = 세 문턱 벌 모두에서 점수 ≥ L0 그리고 기본 벌에서 점수 ≥ 0.5|V|; 기본 벌에서만 성립하면 **불확정(문턱 CI)**; |V| < 11(21 의 반)이면 **평가 불가**. 평균 D 는 조건이 아니라 보고(검토 4: 24 칸 평균 D 의 15 % 는 표준오차 안).
  짝 비교(같은 칸에서 D 차 < −0.1 개선 · > +0.1 악화 · 그 사이 동률)도 보고. 효과 없는 후보는 렌더 흔들림이 1e-4 라 L0 과 동률 → "점수 ≥ L0" 는 넘지만 §4 채택 정책의 "RC 가 L0 보다 좋아야" 조건(아래)으로 거릅니다.
- **R1** 밝기비·어두움비(cu·ac·ci·sc25·sc85, 최대 30 칸): §137 과 **같은 규칙을 그대로**(점수 ≥ L0, 평균 D ≤ 0.85 × L0, 점수 ≥ 0.5|V|, |V| ≥ 18) — §136·§137 과 비교하려고 바꾸지 않음. 밝기비·어두움비를 **따로** 보고(어느 쪽이 교환됐는지).
- **R2** 조각 간 밝기 차: 점수 ≥ L0.
- **R3c-struct·grain**(st·as·ns·sc85, 기본 문턱): 점수 ≥ L0(가드 — 나빠지지 않을 것). 폭 260·208 은 보고만.
- **G1'** CLIP 라벨(ac·ci, 방위 3): 맞는 방위 수 ≥ L0.
- **G2** 박명 색(`genus/twilight-hue.py --horizon`, 지평선 위 전체 화소): 자주 ≤ 0.10, 푸른 ≥ 0.10, 그리고 선형 휘도 L 의 q50 이 **0.5 × L0 이상 2.0 × L0 이하**(L0 = 같은 번들로 같은 단계에서 그린 값; 상한은 L3 의 E_top 하늘 몫이 박명에서 구름을 반대로 밝히는 쪽을 걸러냄) — 두 장면 모두.
- **G3** 끄면 그대로: 셰이더 글자 동일 + 상태 해시 동일(28 장면, `state-hash.js`).
- **G4** 장면별(방위 평균) cloudFrac |Δ| ≤ 25 %(알파는 조명과 무관 — 환경 점검).
- **채택 정책**: 위 규칙을 **모두** '통과'하고 RC 기본 점수가 L0 보다 **큰**(동률 아님) 후보가 **채택 후보**. 여럿이면 RC + R1 점수 합이 큰 쪽, 같으면 단순한 쪽(L1 < L2 < L3). 하나도 없으면 기록만(기본 0). 기본값으로 켜는 것은 사용자 결정.
- **조건부 결과의 읽기(미리 적음, 검토 6)**:
  - RC 통과 · R1 불합격 → "그늘 색은 고쳐졌으나 밝기비는 아님": 기본 끔으로 기록, 다음 자(physics4)는 하늘 기준(렌더 하늘 밝기·K 팔) 부터 다룸.
  - RC 불합격 · R1 통과 → "양은 맞았으나 색이 틀림": E_top 의 하늘 몫(½)·g 를 다음 자의 후보로.
  - RC·R1 통과 · G2 불합격 → 박명에서만 끄는 조건(해 고도)을 다음 자에서 설계, 이 자에서는 채택 안 함.
  - RC '평가 불가'(|V| < 11) → 톤 필터·포화가 칸을 너무 많이 지운 것이므로 결과를 보고만 하고 다음 자에서 사진 표본·노출 자(§127 E2-3 의 autoExposure 가 P0 의 어두운 구름에 맞춰져 있을 가능성)를 다룸(규칙은 안 바꿈).
  - R1 의 밝기비 칸이 L2 에서 사진 q75 위로 가면(검토 물리 9) "밝은 쪽은 물리가 더 밝다고 하는데 노출·톤맵이 P0 에 맞춰짐" 으로 읽고, 노출 자를 다음 자의 첫 항목으로.
- 폭 민감도(R3c)는 §137 과 같이 보고만.

## 6. 예측(렌더 전)
- 칸 수 셈(개발 집합 기준): RC |V| ≈ 14(21 칸 중 톤 필터로 7 무효), L0 ≈ 5/14 — 후보는 기본 벌에서 ≥ 7 이고 L0 보다 커야 하며, 넓게·좁게 벌에서도 ≥ L0. 새 held-out 에서 |V| 가 11 아래로 가는 길: 적운 0.35 장면의 interior 가 한 방위에서 400 화소 미만 + As·St·Ns 가장자리 칸 추가 무효.
- 검토(물리 9)의 밑면 단위 어림(sc, 정오; 하늘 10.5 + 지면 1.7 = 12.2 가 T0 의 어두움비 0.88 에 해당, 기울기 0.04/단위): L0 = 12.2 + thru 23 → 1.80.
  - **L1**: τ_up ≈ 130~165 → thru = 0.28 바닥값 → +5~6 → 어두움비 **≈ 1.1**; 흰 몫이 줄어 shadeBlue 는 **오름**(sc 1.4 → 1.6~1.9) → RC 는 L0 보다 나쁠 가능성. R1 어두움비 칸은 좋아짐.
  - **L2**: 햇빛 6.2 + 하늘 D 1.0 + 충돌 전 하늘 ≈ 0 + 지면 1.7 ≈ 9 → 어두움비 **≈ 0.7**(StSc q25 0.74 경계), shadeBlue ≈ 1.1~1.2(StSc [1.07, 1.33] 안) — RC·R1 어두움비 통과 목표. 밝은 쪽: 꼭대기·해 쪽 면에서 D-항(E·R/2π)이 MS 보다 커질 수 있어 **brightRatio 칸이 사진 q75 위로** 갈 수 있음(R1 의 밝기비 칸 — 따로 보고).
  - **L3**: L2 의 J + takram 하늘항 10.5 → 흰 6 : 푸른 11.5 → shadeBlue ≈ 1.7~2.0 → **RC 통과 불가 예측**(대조 역할). 어두움비 ≈ 1.3~1.4.
- 얇은 권운(ci)은 D ≈ 0.01 이라 L1·L3 는 L0 과 같음; L2 는 하늘항이 π 배 줄어(E_h·½ vs E_h/2) **ci·ac 의 얇은 곳이 어두워질 수 있음** — R1 의 ci 칸·G1' 라벨은 L2 에서 변할 수 있다고 미리 적음.
- 박명(G2): L2 의 하늘항 축소가 자주빛 몫을 줄이고 E_sun·μ0·K 의 붉은 햇빛이 밑면에 더 들어가 자주 몫을 키울 수 있음 — 양방향 가드(0.5~2.0 × L0 휘도)가 가름. L1 은 μ0 와 무관(수직 기둥).
- 어느 후보도 하늘 기준(렌더 하늘 밝기)을 바꾸지 않으므로, 어두움비의 남은 차이는 하늘 쪽 몫.

## 8. 한계(미리 적음)
- 평면평행 두-흐름을 3D 구름 안에서 표본마다 — 옆면에서 새는 빛·이웃 구름 없음. 적운 옆면 그늘(사진 shadeBlue 1.30)은 이 모형 밖.
- 해석적 기둥 τ: 표본의 모양 잡음 배율(소광 ÷ 날씨 밀도)이 기둥 전체에 걸림(±2 배), 날씨 d 를 depth 에서 되찾는 것은 구름 안 표본에서만 정확. 그림자 지도의 가림(이웃 구름)은 MS 항에만 남음.
- takram 그림자 지도 포화(τ ≈ 72 = −ln 1e-4 + 거리 꼬리 3.7~50, quality 의존)는 MS 항의 τ_sun 에 그대로 남아 있음(P0 와 같음). mip ≥ 1 표본의 marchOpticalDepth 0.5 fudge 도 같음.
- MS 하위 옥타브와 D 가 중간 τ(3~20)에서 겹침(둘 다 다중 산란; τ 16 에서 D 의 6 %, τ 3 에서 20 %) — 상수로 가르지 않고 자로만 봄. g 0.85 와 MS 위상(g_eff 0.25)의 불일치는 §1; 다음 자에서 scatterAnisotropy 후보.
- 사진 shadeBlue 는 JPEG 톤 곡선 영향(톤 배율 필터 0.85~1.2 밖은 못 잡음), 제외 후 표본 n 13~39(Ci 13 — 좁음). 사진 allCloud(p95 < 0.15) 사진(St·As 다수)은 마스크 = 전체 화면이라 렌더(알파, 틈 있음)와 영역이 다름.
- 사후 결정으로 표시: shadeBlue 자체·분위 0.3/0.7·최소 400/100 화소·ci 제외·|V| ≥ 11 은 §137 렌더(지금은 개발 집합)를 본 뒤 정했음. 그래서 held-out 을 새로 뽑음(§3).
- g 고정 0.85; 얼음 0.75~0.8 미적용. μ0 바닥값 0.05 는 해 0~3° 에서 햇빛 몫을 최대 2.5 배 과대(G2 장면 μ0 0.36~0.41 은 해당 없음).
